# 링크된 프리팹 · 덮어쓰기 · 중첩 (2026-11-21)

[Engine_Foundation_Gaps.md](Engine_Foundation_Gaps.md) 의 9위 후보입니다. 지금은 프리팹을 꺼내면 복사본이 되고, 씬에 원본 링크가 남지 않습니다.
이 문서는 작업 지시서가 아니라 **완료 조건 체크리스트**이고, 항목을 모두 만족하면 끝입니다. GUID · 경로 정책은
[Object_References.md](Object_References.md) 를 그대로 따릅니다.

## 1. 조사 요약

### 1-1. 지금 코드 (2026-11-21)

| 곳 | 지금 | 문제 |
|---|---|---|
| `PrefabManager::save` | 액터 서브트리를 씬과 같은 액터 블록으로 씀(프리팹 v5, 첫 블록 = 루트) | 링크 정보가 없음 |
| `PrefabManager::spawn` | `readScene(Fresh)` 로 꺼냄(GUID 를 새로 주고 세트 안 참조를 바꿈) | 꺼낸 뒤에는 보통 액터와 같음 |
| 씬 v6 (`SceneSerializer`) | `ACTOR:` 블록, 부모는 블록 순번(`PARENT:`), 컴포넌트는 `COMPONENT:` 블록의 `이름=값` 줄 | 프리팹 인스턴스를 표현할 수 없음 |
| 에디터 Undo · 붙여넣기 · Play 되돌리기 | 모두 액터 블록 글(`writeActorSet` · `writeScene`)로 떠 두고 다시 읽음 | 링크 정보를 글에 담으면 모두 따라옴 |
| 아웃라이너 · 디테일 패널 | 프리팹 저장 단추만 있음 | 인스턴스 표시 · 덮어쓰기 표시가 없음 |
| 핫리로드(`HotReloader`) | 모델 · 텍스처 · 씬 · import.ini | 프리팹은 남음 목록에 있음 |

### 1-2. 다른 엔진

- **Unity:** 씬은 인스턴스마다 `PrefabInstance` 하나(원본 GUID + `m_Modifications` = (대상 객체, 속성 경로, 값) 목록 + 지운 컴포넌트 ·
  추가한 컴포넌트 · 추가한 GameObject 목록)를 씁니다. 인스턴스 안 객체의 파일 ID 는 `원본 파일 ID XOR 인스턴스 파일 ID` 로
  결정적으로 만듭니다. 덮어쓰기는 "기록"(편집 경로가 남김)이고, 값이 원본과 같아져도 남습니다. 중첩 프리팹 · 변형(Variant)은
  같은 구조를 재귀로 씁니다. 인스펙터는 덮어쓴 속성을 굵게 + 왼쪽 파란 막대로 보이고, 우클릭으로 Revert · Apply to Prefab.
  Unpack 은 링크를 끊고 복사본으로 바꿉니다.
- **Unreal:** 레벨 인스턴스 · 블루프린트. 블루프린트 인스턴스는 클래스 기본값(CDO)과 다른 속성만 저장합니다(델타 직렬화 = "비교").
  디테일 패널은 기본값과 다른 속성 옆에 되돌리기 화살표를 둡니다. 컴포넌트 추가는 되지만 상속한 컴포넌트는 지울 수 없습니다.
- **Godot:** `.tscn` 에서 인스턴스 노드는 `instance=ExtResource(...)` 한 줄과, 원본과 다른 속성만 적은 같은 이름의 노드 줄입니다
  ("비교" 방식). 인스턴스 안에 노드를 더하면 `parent="인스턴스/경로"` 로 붙습니다. "Editable Children" · "Make Local"(링크 끊기).

### 1-3. 공통 구조

1. 인스턴스 = 원본 경로 + 덮어쓰기 목록. 덮어쓰지 않은 값은 원본을 따릅니다.
2. 인스턴스 안 객체와 원본 안 객체의 **안정된 짝**(Unity 파일 ID 파생, Godot 노드 경로).
3. 덮어쓰기는 (짝 · 컴포넌트 · 속성 경로 → 값). 추가 · 삭제는 따로 표현합니다.
4. 중첩은 같은 구조의 재귀, 순환은 거부합니다.
5. 에디터는 덮어쓰기 표시 · 되돌리기 · 원본에 적용 · 링크 끊기를 줍니다.

## 2. 결정

- **D1 덮어쓰기는 "비교"로 얻습니다(Unreal · Godot 방식).** 저장할 때 인스턴스 액터를 글로 쓴 결과와 원본(같은 GUID 로 바꾼 것)을
  속성마다 비교해, 다른 것만 씁니다. Unity 처럼 편집 경로마다 기록하려면 기즈모 · 디테일 칸 · 콘솔 · 게임 코드의 모든 변경 경로를
  손봐야 하고, 빠뜨린 경로는 조용히 값을 잃습니다. 비교는 경로를 몰라도 되고, 원본과 같은 값은 저절로 덮어쓰기에서 빠집니다.
  대신 값이 원본과 다르기만 하면(읽을 때 고쳐진 값 등) 덮어쓰기로 남습니다. 원본 파일도 같은 쓰기 함수가 썼으므로 보통은 같습니다.
- **D2 비교 기준은 "이 인스턴스를 만든 원본 글"입니다.** 에디터는 월드 서비스 `PrefabSourceCache` 에 읽은 프리팹 글을 경로별로 둡니다.
  디스크의 프리팹이 바뀌어도(다른 도구 · 다른 에디터) 캐시와 비교하므로, 원본 값이 덮어쓰기로 잘못 남지 않습니다. 캐시를 새 글로
  바꾸는 것은 인스턴스를 다시 펼칠 때뿐입니다(D7). 게임 실행 파일은 캐시 없이 파일에서 바로 펼칩니다(저장하지 않음).
- **D3 짝 = 원본 GUID, 인스턴스 GUID = 결정적 파생.** 인스턴스 루트 GUID 는 씬에 적고, 다른 액터는 `derive(루트 GUID, 원본 GUID)`
  (splitmix64 두 번 섞기, 0 이면 1)로 만듭니다. 그래서 다시 펼쳐도 같은 GUID 이고, 씬의 다른 액터가 인스턴스 안 액터를 가리키는
  참조(`actor:<16진수>`)가 유지됩니다. 원본 안을 가리키던 참조는 같은 함수로 바꿔 이번 인스턴스 안을 가리킵니다(Fresh 와 같은 효과).
  붙여넣기 · 복제(Fresh)처럼 파생 값과 다른 GUID 가 된 액터는 `MEMBER_GUID:` 줄로 적어 다시 읽어도 같게 합니다.
  중첩은 재귀로 합성됩니다(B 의 액터는 A 안에서 `derive(gB, 원본)`, 씬에서는 그 값을 다시 `derive(gA, ·)`).
- **D4 속성 경로.** 액터 수준 = 파일 키(`POS` · `ROT` · `QUAT` · `SCALE` · `ACTIVE` · `TAGS`, 그 밖의 줄도 같은 규칙) · `NAME`(이름) ·
  `@PARENT`(인스턴스 안 부모의 짝). 컴포넌트 = `<형>[<같은 형 안 순번>].<칸>`(예 `LightComponent[0].intensity`, `enabled` 포함).
  짝 · 경로가 글이므로 등록되지 않은 컴포넌트(UnknownComponent)도 같은 규칙으로 다룹니다.
- **D5 추가 · 삭제 방침.**
  - 원본에 없는 컴포넌트: 그 컴포넌트의 모든 칸을 덮어쓰기로 씁니다(순번이 원본 수를 넘으면 펼칠 때 덧붙임).
  - 원본에 있는 컴포넌트를 지움: `REMOVE:<짝> <형>[<순번>]`.
  - 인스턴스 안 액터를 지움: `REMOVE:<짝>`(그 서브트리도 빠짐). 루트를 지우면 인스턴스 전체가 사라지므로 기록할 것이 없습니다.
  - 인스턴스 안에 더한 액터: 인스턴스 소속이 아닌 보통 씬 액터이고, 부모가 인스턴스 안 액터면 `PARENT_GUID:<16진수>` 로 붙습니다
    (Godot 의 `parent=` 와 같은 자리). 다른 프리팹 인스턴스를 그 아래 두어도 같습니다.
  - 인스턴스 안 액터를 인스턴스 밖(또는 더한 액터 아래)으로 옮기면 그 액터는 인스턴스에서 빠져 보통 액터가 됩니다(삭제 + 추가).
    인스턴스 안에서 부모만 바꾸면 `@PARENT` 덮어쓰기입니다.
- **D6 파일 형식.** 씬 v7 · 프리팹 v6 에 인스턴스 블록을 더합니다. 옛 씬 · 프리팹(v6 이하 · v5 이하)은 그대로 읽히고, 인스턴스
  블록이 없으므로 링크 없는 복사입니다. 새 엔진이 쓰는 파일은 인스턴스가 없으면 머리 줄만 다릅니다.
  ```
  PREFAB:/Game/prefabs/Lamp.hprefab
  GUID:<인스턴스 루트 GUID>
  PARENT:<블록 순번>                 (또는 PARENT_GUID:<16진수>)
  OVERRIDE:<짝> POS=1 0 2
  OVERRIDE:<짝> LightComponent[0].intensity=3
  REMOVE:<짝>                        (액터)   REMOVE:<짝> AudioComponent[0]   (컴포넌트)
  MEMBER_GUID:<짝> <GUID>
  END_PREFAB
  ```
  블록 하나가 블록 순번 하나를 차지합니다(뒤 블록의 `PARENT:` 가 인스턴스 루트를 가리킬 수 있음). 펼친 뒤 `readScene` 이 돌려주는
  슬롯은 펼친 액터마다 하나입니다. Undo 스냅숏 · 붙여넣기 글(`writeActorSet`)은 펼친 액터 블록에 `PREFAB_SOURCE:`(루트) ·
  `PREFAB_PAIR:`(소속 액터) 줄을 더한 "전체" 형식이라, 지우기 · 되살리기 · 복사해도 링크가 따라옵니다.
- **D7 다시 펼침.** 씬을 열 때 원본 + 덮어쓰기로 인스턴스를 만듭니다. 에디터에서 프리팹을 저장하거나(디테일 패널 · 원본에 적용)
  감시가 프리팹 파일 변경을 알리면, 그 프리팹에 기대는(중첩 포함) 인스턴스마다 ① 옛 캐시 기준으로 덮어쓰기를 구하고 ② 서브트리를
  지우고 ③ 캐시를 새 글로 바꾸고 ④ 다시 펼친 뒤 같은 GUID 액터에 옛 실행 번호를 돌려줍니다(Undo 커맨드가 그대로 이어짐).
  다시 펼침은 파일 동작의 결과라 Undo 이력에 넣지 않습니다.
- **D8 순환 · 없는 원본.** 펼치는 중인 경로가 다시 나오면 오류로 거부합니다. 안쪽 어디서 순환이 나와도 그 원본 전체를 거부해
  (가장 바깥 인스턴스 블록이 빈 루트가 됨) 씬에 적힌 덮어쓰기를 잃지 않습니다. 원본 파일이 없어도 빈
  루트(아웃라이너 종류 칸 `Prefab?`)를 만들고, 인스턴스 블록의 줄(덮어쓰기)을 그대로 기억했다가 다시 저장할 때 그대로 씁니다(값을 잃지 않음). 프리팹을 저장할 때
  내용 안의 인스턴스가 저장할 파일에 (중첩으로라도) 기대면 저장을 거부합니다. 단, 루트가 바로 그 프리팹의 인스턴스면(인스턴스를
  고쳐 같은 이름으로 저장) 루트 인스턴스를 풀어 보통 액터로 씁니다.
- **D9 원본에 적용 · 되돌리기 · 링크 끊기(에디터).** 되돌리기 = 그 속성을 원본 값으로 다시 넣기(액터 · 컴포넌트를 글로 다시 읽어 넣는
  커맨드, Undo 가능). 원본에 적용 = 원본 프리팹 글에서 그 짝의 블록(중첩이면 안쪽 인스턴스 블록의 덮어쓰기)을 고쳐 저장 → D7.
  파일 동작이라 Undo 하지 않습니다(Unity 와 같음). 링크 끊기 = 소속 정보를 지우는 커맨드(Undo 가능, Unity Unpack · Godot Make Local).
- **D10 범위 줄임.** 프리팹 변형([선택])은 이번에 하지 않습니다. 형식상 프리팹 파일의 첫 블록이 인스턴스 블록이면 변형이 되지만,
  에디터 흐름(변형 만들기 메뉴)과 시험이 필요해 "남음"에 둡니다. 덮어쓰기 표시는 디테일 패널의 속성 줄 이름 색 · 섹션 머리의
  되돌리기 · 적용 단추로 하고, 우클릭 메뉴는 만들지 않습니다.
- **D11 디테일 표시 갱신.** 덮어쓰기 표시는 디테일을 만들 때 원본과 비교해 한 번 구합니다. 고른 액터가 인스턴스 소속이면 커맨드가
  쌓일 때마다(기즈모 · 디테일 칸 · Undo) 디테일을 다시 만들어 표시를 맞춥니다. 매 프레임 비교하지 않습니다(원본을 펼치는 비용).
- **D12 게임 실행 파일.** 게임은 씬을 열 때만 펼치고 저장하지 않으므로 캐시 서비스를 붙이지 않고 파일에서 바로 읽습니다. 에셋 참조
  색인은 인스턴스 블록의 원본 경로와 덮어쓰기 값의 에셋 경로(`OVERRIDE:<짝> <경로>=/Game/…`)를 참조로 셉니다(옮기기 때 함께 바뀜).
