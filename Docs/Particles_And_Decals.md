# 파티클 · VFX · 데칼 (2026-11-20)

[Engine_Foundation_Gaps.md](Engine_Foundation_Gaps.md) 의 6위 후보입니다. 지금 엔진에는 불꽃 · 연기 · 먼지 · 불티 같은 효과를 낼 파티클이 없고,
바닥의 얼룩 · 탄흔 · 표시처럼 표면에 무늬를 덧칠하는 데칼도 없습니다. 이 문서는 작업 지시서가 아니라 **완료 조건 체크리스트**이고,
항목을 모두 만족하면 끝입니다.

### 1-2. 다른 엔진

- **Unreal (Cascade → Niagara):** 이미터 = 생성(Spawn Rate · Spawn Burst) + 갱신 모듈(수명 · 속도 · 중력 · 감쇠 Drag · Color/Scale Over Life 곡선) +
  렌더러(Sprite · Mesh · Ribbon). CPU · GPU 시뮬레이션을 고름, 로컬 · 월드 공간(`bLocalSpace`), 결정성(`Deterministic` + 시드),
  최대 개수. 스프라이트 렌더러의 정렬 모드(None · ViewDepth · ViewDistance), 방향(FaceCamera · FaceCameraPosition, VR 은 위치 쪽을 권함),
  Sub UV. 반투명은 이미터 단위로 정렬된 뒤 이미터 안을 정렬합니다. 데칼: 지연 렌더링은 G-Buffer 데칼, 포워드 · 모바일은 **DBuffer 데칼**
  (깊이 프리패스 뒤 데칼을 별도 버퍼에 그려 베이스 패스가 읽음).
- **Unity (Shuriken · VFX Graph):** `ParticleSystem` 모듈 = Emission(rate · bursts) · Shape(Cone · Sphere …) · Start Lifetime/Speed/Size/Color ·
  Color/Size over Lifetime · Limit Velocity(감쇠) · Max Particles · Simulation Space(Local/World) · `randomSeed` + `useAutoRandomSeed`.
  `ParticleSystemRenderer` 의 정렬 모드(By Distance · Oldest/Youngest), 가산 · 알파 섞기는 머티리얼 셰이더. URP 데칼 프로젝터는
  **DBuffer** 와 **Screen Space**(깊이에서 위치를 되살려 덧칠) 두 기법.
- **Godot 4:** `CPUParticles3D` · `GPUParticles3D`(amount · lifetime · explosiveness = 한 번에 터뜨리기 · `fixed_fps` · `seed`(4.3) ·
  `local_coords` · draw_order(Index · Lifetime · View Depth)), 빌보드 모드. 데칼은 `Decal` 노드: Forward+ 에서 **클러스터 데칼**
  (상자들을 클러스터에 넣고, 물체 셰이더가 조명 전에 알베도 · 법선 · ORM 을 아틀라스에서 읽어 덮어씀). 모바일 렌더러는 물체마다 데칼 상한 8개.
- **id Tech 6 (DOOM 2016):** 클러스터 포워드에서 데칼도 조명처럼 클러스터에 넣고, 불투명 셰이더가 조명 전에 데칼을 섞습니다(포워드 데칼).

### 1-3. 공통 구조

1. 이미터 = **생성 규칙(비율 · 터뜨리기) + 초기값(수명 · 속도 분포 · 크기 · 색) + 수명 동안의 갱신(힘 · 감쇠 · 수명 비율 곡선) + 상한**.
   셋 다 로컬/월드 공간과 시드를 둡니다.
2. 그리기는 **카메라를 보는 사각형의 인스턴싱**, 텍스처 × 파티클 색, 가산 또는 알파 섞기, 깊이 시험만 하고 쓰지 않습니다.
3. 알파 섞기는 **이미터끼리 정렬 → 이미터 안 정렬**이 기본입니다(UE · Unity · Godot 의 View Depth).
4. 포워드 렌더러의 데칼은 **DBuffer(별도 버퍼를 베이스 패스가 읽음)** 또는 **포워드/클러스터 데칼(물체 셰이더가 데칼 목록을 직접 봄)** 입니다.
   화면 공간(깊이 재구성) 방식은 조명 뒤에 덧칠해 조명 · 그림자를 받지 않거나 별도 G-Buffer 가 필요합니다.

## 2. 결정

- **D1 시뮬레이션 모듈(`src/vfx/`, 의존 core · math):** 장면 · 렌더러와 무관한 순수 계산입니다. `ParticleEmitterDesc`(설정) · `ParticleSim`(상태와
  `step(dt, 이미터 월드 행렬, 생성 중)`) · `buildInstances`(그릴 인스턴스) · `sortBackToFront`. GPU 없이 시험합니다(`HarukaParticleTest`).
  렌더러는 인스턴스 형과 정렬 함수만 씁니다(규칙 표에 `vfx` 를 넣고 renderer · components 가 봄). core 는 씬 파일 글자의 실수 표기
  (`TextFloat.hpp`)와 계측 매크로 때문에 봅니다.
- **D2 이미터 설정:** 생성률(개/초) · 한 번에 터뜨리기(시작 때 개수) · 반복 여부 · 지속 시간, 수명(최소 ~ 최대), 초기 속도(최소 ~ 최대, 모양
  Cone(반각) · Sphere), 생성 반경, 중력(벡터, m/s²) · 감쇠(1/s, `v *= exp(-drag dt)`), 크기(m) · 크기 곡선 · 색 곡선(수명 비율 0 ~ 1 의 키,
  선형 보간, 색은 선형 HDR + 알파), 회전 속도(도/초, 시작 각은 무작위), 최대 개수(1 ~ 65,536), 공간(Local · World), 시드, 섞기(Additive ·
  Alpha), 텍스처 모양. 근거: 세 엔진의 공통 최소 모듈 집합(1-3 의 1)이고 Unity Shuriken 의 이름을 따릅니다.
- **D3 결정성:** 이미터마다 PCG32 하나를 시드로 만들고, 생성할 때만 난수를 씁니다(갱신은 난수 없음). 같은 시드 + 같은 dt 수열이면 같은
  결과입니다. 시드 0 은 "고정 시드 0" 이고, 무작위 시드는 두지 않습니다(재현이 기본, 다르게 하려면 시드를 다르게). 생성 시간 누적은 dt 의
  합(소수 생성은 다음 틱으로 넘김)이라 dt 를 쪼개도 개수가 거의 같습니다(실수 누적 오차만큼). 근거: Niagara `Deterministic` · Godot `seed` 와 같은 뜻이고,
  창 없는 PNG 검증(`--fixed-dt`)이 이 성질에 기댑니다.
- **D4 상한과 제거:** 수명이 다한 파티클은 그 스텝에 빠집니다(마지막과 바꿔 지우기, 순서는 정렬이 정함). 최대 개수에 닿으면 새 생성을 버립니다
  (UE · Unity 와 같음, 오래된 것을 밀어내지 않음).
- **D5 시간:** 컴포넌트는 `Display` 틱 그룹에서 프레임 dt(시간 배율이 곱해진 값)로 갑니다. 일시정지면 틱이 없어 멈춘 그대로 그려집니다.
  시뮬레이션 틱(물리 포함) 뒤에 돌기 때문에 물리로 움직이는 액터에 붙어도 그 틱의 자리에서 생성합니다. 한 틱 dt 는 0.1 초로 자릅니다(창을 끌다 멈춘 뒤 한꺼번에 쏟아지지 않게).
- **D6 공간:** World 는 생성할 때 월드 위치 · 속도로 바꿔 두고, Local 은 이미터 로컬에 두었다가 인스턴스를 만들 때 월드 행렬을 곱합니다
  (로컬의 중력은 월드 방향을 로컬로 돌려 적용). 크기에는 액터 크기를 곱하지 않습니다(Unity 의 Scaling Mode = Local 과 다름, 단순함 우선).
- **D7 그리기(`GeometryPass` 의 파이프라인 묶음 + `GeometryPass_particles.cpp`):** 패널처럼 메인 패스가 소유합니다(렌더 패스 두 벌 ·
  핫 리로드 · 크기 변경을 이미 처리하므로 별도 패스를 두지 않음). 정점 버퍼 없이 정점 번호 6개로 사각형을 만들고, 파티클은 **인스턴스 정점 버퍼**(48 B: 위치 ·
  크기, 선형 색 · 알파, 회전 · 텍스처 칸)입니다. 프레임 슬롯마다 호스트 버퍼 하나(최대 65,536 개, 3 MB)를 둡니다. 반투명 서브패스(2)에서
  반투명 메시 뒤 · 월드 UI 패널 앞에 그립니다. 깊이 시험(Reverse-Z GREATER_OR_EQUAL) 하고 쓰지 않습니다. 색은 알파를 곱한 값을 내고,
  알파 섞기는 (ONE, ONE_MINUS_SRC_ALPHA), 가산은 (ONE, ONE). HDR 알파(후처리 가중치)는 (ZERO, ONE) 으로 그대로 둡니다. 파이프라인은 단안 ·
  멀티뷰 × 두 섞기 = 4개입니다. 조명 · 그림자 · 안개는 받지 않습니다(남음).
- **D8 방향:** 사각형은 **두 눈의 가운데 위치를 바라봅니다**(UE 의 FaceCameraPosition). 두 눈이 같은 사각형을 보고 머리를 돌려도 돌지 않습니다
  (VR 에서 카메라 평면 정렬은 고개를 기울이면 파티클이 같이 돕니다). 위쪽은 월드 +Y 를 시선에 수직으로 맞춘 것이고, 바로 위 · 아래를 볼 때는
  월드 +Z 로 바꿉니다.
- **D9 정렬:** 알파 이미터는 **이미터끼리(이미터 중심과 눈 가운데의 거리, 먼 것부터) + 이미터 안(파티클 거리, 먼 것부터)** 둘 다 합니다.
  가산 이미터는 순서가 결과를 바꾸지 않아 이미터 안 정렬을 하지 않고, 이미터끼리 순서에만 들어갑니다. 같은 거리는 생성 순번으로 정해 결과가
  늘 같습니다. 정렬은 렌더러가 눈 가운데를 안 뒤 프레임마다 합니다(XR 의 눈 위치는 렌더러만 알기 때문). 이미터 안 정렬은 거리 제곱 비트를
  뒤집은 32비트 키의 안정 기수 정렬(8비트 × 4번)입니다. 처음 쓴 비교 정렬(`std::sort`)은 1만 개에 0.61 ms 여서 바꿨습니다(4절).
  합이 상한(65,536)을 넘으면 먼 이미터부터 잘립니다(가까운 효과를 남김).
- **D10 텍스처:** 엔진이 만드는 **모양 아틀라스 하나**(128 × 128 RGBA8 UNORM, 2 × 2 칸: 부드러운 원 · 단단한 원 · 고리 · 별빛)를 씁니다.
  색은 파티클 색 × 텍스처입니다. 근거: 낱장 텍스처 에셋 · 가져오기 설정이 아직 없고(04 · 08 항목), 흔한 효과(불티 · 연기 · 먼지 · 빛 번짐)는
  이 넷으로 됩니다. 텍스처 파일 · Sub UV 는 남음입니다.
- **D11 데칼(포워드 데칼):** Godot Forward+ · DOOM 의 방식으로 **불투명 셰이더(pbr.frag)가 조명 전에 데칼 상자 목록을 봅니다**. 상자 투영
  (로컬 −Y 방향으로 투영 = 회전 없는 데칼은 바닥에 찍힘(Godot 과 같음), 상자는 액터 월드 × `size` 의 로컬 [-0.5, 0.5]³)이고, 모양은 셰이더가 계산하는 마스크(원 · 부드러운 원 · 고리 · 사각)입니다. 알베도를 데칼 색으로
  덮어쓰거나(Replace) 곱해 섞고(Multiply), 거칠기도 바꿀 수 있습니다. 투영 방향과 표면 법선이 이루는 각으로 옅어지게 해 옆면이 늘어나지
  않게 합니다. 한 프레임 최대 8개이고 FrameUBO 끝에 붙입니다(개수 0 이면 반복문이 돌지 않음).
  근거: 화면 공간 데칼(깊이 재구성)은 메인 패스 밖에서 HDR 에 덧칠해 조명 · 그림자 · 안개를 받지 못하고, 반투명 서브패스 안에서는 깊이를
  읽을 수 없습니다(입력 첨부로 바꾸면 렌더 패스 · 모든 파이프라인이 바뀜). DBuffer 는 별도 타깃 · 패스가 들어 Quest 타일 GPU 의 대역을 씁니다.
  포워드 데칼은 패스 · 타깃을 늘리지 않고 조명을 그대로 받으며, 데칼이 없으면 비용이 0 입니다. 데칼 텍스처는 D10 과 같은 이유로 남음입니다.
  반투명 물체에도 붙는 것은 받아들입니다(같은 셰이더).

### 4-2. 측정 (1만 개, RTX 3080 · GPU 1, 두 눈 1024² 멀티뷰 · MSAA 4x, 600 프레임 중앙값)

이미터 하나(비율 10,000/초 · 수명 1 초 · 상한 10,000, 크기 6 cm, 눈에서 약 3 m)를 그린 장면과 같은 장면에서 이미터만 뺀 장면을 비교했습니다.
CPU 구간은 `--trace-frames=300-500` 의 `HPROF_SCOPE` 중앙값입니다.

| 구간 | 없음 | 알파 1만 | 가산 1만 |
|---|---|---|---|
| CPU 시뮬레이션(`Particles.Simulate`) | - | 97 µs | 97 µs |
| CPU 정렬 · 잇기(`Renderer.Particles`) | 0 | 181 µs(비교 정렬 때 608 µs) | 17 µs |
| GPU 메인 패스 | 0.111 ms | 0.487 ms | 0.480 ms |
| GPU 프레임 합 | 0.368 ms | 0.744 ms | 0.739 ms |

- 1만 개의 GPU 비용은 두 눈 합 약 0.37 ms 입니다(작은 입자라 오버드로가 적은 경우). 큰 연기 입자는 화면을 덮는 면적에 비례해 늘어나므로
  Quest 에서는 오버드로를 따로 재야 합니다(헤드셋 확인 목록).
- 인스턴스 버퍼는 파티클을 처음 그릴 때 프레임 슬롯마다 3 MB(65,536 × 48 B)를 잡습니다. 파티클이 없는 게임은 잡지 않습니다.
