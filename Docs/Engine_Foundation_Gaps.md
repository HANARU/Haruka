# 엔진 기반 공백 감사 — 필수인데 기능이 부족한 것 (2026-11-20)

2026-11-19 에 "중요하지만 고려하지 않았던 요소"를 찾아 액터 ID · 참조([Object_References.md](Object_References.md)), 크래시 보고
([Crash_Reporting.md](Crash_Reporting.md))를 넣었습니다. 이 문서는 그 뒤 남은 후보에 사용자가 지적한 **애니메이션**을 더해, 게임 엔진에
필수인데 지금 코드에서 비어 있거나 약한 기능을 같은 기준으로 다시 감사한 결과입니다. 근거는 2026-11-20 코드(커밋 전 작업 트리 포함)이고,
일반 엔진(Unreal · Unity · Godot)이 기본으로 주는 것을 비교 기준으로 삼았습니다.

후보마다 **현재 상태 / 부족한 점 / 의존 관계 / 우선순위 / 검증 체크리스트**를 적습니다. 착수한 후보는 따로 설계 문서를 만들고 여기서 연결합니다.

## 2. 순위를 정한 기준과 결정

순위는 (a) 이것이 없으면 만들 수 없는 게임의 범위, (b) VR · Quest 에서의 영향, (c) 이미 있는 코드를 재사용할 수 있는 정도,
(d) 다른 후보의 선행 조건인지를 보고 정했습니다.

**1위를 애니메이션으로 정했습니다(2026-11-20, 사용자 부재 중 자체 판단).** 근거는 다음과 같습니다.
- 사용자가 대표 공백으로 직접 지적했습니다.
- 캐릭터 · 문 · 기계 · 손 동작처럼 움직이는 콘텐츠는 모두 애니메이션이 있어야 만들 수 있습니다. 지금은 glTF 에 애니메이션이 들어 있어도 버립니다.
- 손 쥐기 작업에서 스킨 자료형 · 로더 · 캐시 · CPU 스키닝 · 렌더 경로를 이미 만들어 두었습니다. 그래서 새로 만들 부분(클립 · 샘플러 · 재생기 ·
  블렌딩)에 집중할 수 있고, 창이나 GPU 없이 시험할 수 있는 순수 계산이 대부분입니다.

2위인 비동기 로딩은 VR 에서 영향이 가장 크지만, 지금 게임은 XR 세션 전에 시작 씬 하나만 읽습니다. 그래서 피해가 실제로 드러나는 것은 레벨이 둘
이상인 게임부터입니다. 또 작업 시스템 · 메가버퍼 해제 · 업로드 예산까지 함께 바꾸는 큰 작업이라, 애니메이션 다음 단계로 두었습니다.

## 3. 후보별 상세

### 3-1. 애니메이션 (1위)

- **현재 상태:** `assets/Skin.hpp` 의 `SkinSourceData` · `hskin::`(계층 순서 · 전역 행렬 · 팔레트 · 선형 블렌드 스키닝), `GltfLoader::readSkin`
  (관절 · 쉬는 자세 TRS · 역바인드 · JOINTS_0/WEIGHTS_0), `.gasset` 캐시 v7 의 스킨, `SkinnedMeshComponent`(관절 회전 설정 · `skinInto`),
  렌더러의 CPU 스키닝 → `GpuScene::skinArena`(프레임 슬롯마다 32,768 정점) 경로, 매 프레임 스킨 정점 AABB 컬링. 시간 보간 수학은
  `math/Damping.hpp`(ease · 스프링) · `math/Curves.hpp`(hermite · bezier · Catmull-Rom) · `math/Ik.hpp`(두 뼈 IK) 에 있습니다.
- **부족한 점:**
  - glTF `animations` 를 읽는 곳이 없습니다(채널 · 샘플러 · STEP · LINEAR · CUBICSPLINE).
  - 클립 · 재생기(시간 · 반복 · 속도) · 크로스페이드 · 가산 블렌딩 · 상태 기계 · 이벤트(notify) · 루트 모션이 없습니다.
  - 포즈는 관절 회전만 바꿀 수 있습니다. 이동 · 배율은 쉬는 자세로 고정입니다.
  - 모프 타깃(glTF `targets` · `weights`)을 읽지도 그리지도 않습니다.
  - 스킨이 없는 노드 애니메이션(문 · 기계 같은 강체 계층)을 재생할 수 없습니다.
  - 에디터 미리보기 · 뼈대 표시가 없고, `SkinnedMeshComponent::localBounds` 는 쉬는 자세 고정값입니다.
  - JOINTS_1 은 버립니다(문서 [Hand_Grasp_Design.md](Hand_Grasp_Design.md) 의 "큰 4개만 남기고 다시 정규화"와 다름).
  - [Engine_Specification.md](Engine_Specification.md) 5-2 의 "스키닝 · 애니메이션 · 모프 없음"은 스키닝 부분이 낡았습니다.
- **의존 관계:** 선행 조건은 없습니다(스킨 경로가 있음). 뒤 후보 중 내비게이션 · AI(캐릭터 이동)와 게임플레이 도구(이벤트)가 이것을 씁니다.
  GPU 스키닝은 캐릭터가 많아질 때 따로 다룹니다.
- **검증 체크리스트:** [Animation_System.md](Animation_System.md) 의 체크리스트가 정본입니다.

### 3-2. 비동기 로딩 · 레벨 전환 · 언로드 (2위)

- **현재 상태:** `AssetManager::loadAll` 이 동기이고, 텍스처 업로드는 `RenderContext::endOneTimeCmd` 에서 `vkQueueWaitIdle` 을 부릅니다. 메가버퍼는
  메시를 따로 해제하지 않습니다(`GpuScene.cpp` "never individually freed"). 게임은 `openInitialScene` 으로 시작 씬만 엽니다. 비동기는 miniaudio
  소리 읽기뿐입니다.
- **부족한 점:** 백그라운드 읽기 · 디코드, 메인 스레드 업로드 예산(프레임마다 몇 MB), 씬 전환 API · 로딩 화면, XR 컴포지터 레이어(로딩 중 머리 추적
  유지), 메시 · 텍스처 해제와 메가버퍼 조각 관리.
- **의존 관계:** 작업 스레드(작은 작업 큐)가 먼저 있어야 합니다. 텍스처 압축(7위)과 같은 업로드 경로를 지나므로 함께 설계하면 좋습니다.
- **우선순위 근거:** VR 영향은 가장 크지만, 지금 게임은 XR 전에만 읽어서 피해가 드러나는 것은 여러 레벨 게임부터입니다.
- **검증 체크리스트:**
  - [ ] 큰 glTF 를 Play 중에 읽는 동안 프레임 시간 99분위가 예산(90 Hz 기준 11.1 ms) 안.
  - [ ] 씬 A → B 전환 뒤 A 의 메시 · 텍스처 메모리가 돌아옴(메가버퍼 사용량 로그).
  - [ ] 로딩 중 XR 프레임 제출이 끊기지 않음(헤드셋).
  - [ ] 읽기 실패 · 취소 경로에서 누수 · 검증 오류 0.

### 3-3. 저장 게임 · 사용자 설정 (3위)

- **현재 상태:** 쓰기 루트 `happ::inWriteRoot`(게임은 `%LOCALAPPDATA%`), `Config/engine.ini` 의 두 겹 덮어쓰기(기술 한도), 에디터 상태 파일. 소리 버스
  볼륨은 API 만 있고 저장하지 않습니다. 게임 설정 화면이 없습니다([Packaging_Design.md](Packaging_Design.md)).
- **부족한 점:** 저장 슬롯 API(이름 · 버전 · 원자적 쓰기 · 손상 감지), 사용자 설정 계층(그래픽 품질 · 소리 버스 · 입력 재지정 · 편안함 설정)을
  쓰기 루트에 보존하는 것.
- **의존 관계:** 원자적 쓰기는 참조 체계의 `hrefs::applyMove` 쓰기 방식을 재사용할 수 있습니다. 입력 재지정 저장(10위)과 오디오 버스 저장이 이것을 씁니다.
- **검증 체크리스트:**
  - [ ] 저장 → 다시 시작 → 불러오기 왕복(값 · GUID 참조 유지).
  - [ ] 쓰는 도중 끊긴 파일을 읽으면 이전 저장본을 씀(원자적 쓰기).
  - [ ] 옛 버전 저장 파일을 읽어 새 필드는 기본값.
  - [ ] 설정을 바꾸고 다시 시작하면 그 값(그래픽 · 소리 · 입력).

### 3-4. 게임플레이 기본 도구 · CVar · 콘솔 (4위)

- **현재 상태:** `IGameModule` 수명 함수, 컴포넌트 `onAttach` · `onStart`(첫 틱) · `onEnable` · `onDisable` · `onDestroy` · `tick`, `HDelegate` · `HEvent`,
  `World::onActorSpawned` · `onActorDestroyed`, 월드 서비스, `HActorRef`. 명령줄 옵션 약 40개와 ini 는 시작할 때만 읽습니다.
- **부족한 점:** 타이머 · 지연 호출, 액터 · 컴포넌트 태그, 전역 이벤트 버스, 틱 순서 그룹, 컴포넌트 단위 BeginPlay · EndPlay, 이름으로 등록하는 실행
  중 변수(CVar)와 콘솔(에디터 · 헤드셋 안 패널), C++ 핫리로드나 스크립트 계층.
- **의존 관계:** 없음. CVar 는 사용자 설정(3위) · 계측(5위)과 이름 체계를 함께 쓰면 좋습니다.
- **검증 체크리스트:**
  - [ ] 타이머가 일시정지 · 시간 배율을 따르고, 액터가 지워지면 함께 취소됨.
  - [ ] CVar 를 명령줄 · ini · 콘솔에서 같은 이름으로 바꾸고, 바뀐 값이 다음 프레임에 반영됨.
  - [ ] 태그 질의가 구조 버전 캐시로 프레임마다 훑지 않음.

### 3-5. CPU 구간 계측 (5위)

- **현재 상태:** `core/FrameTimings.hpp` 의 고정 18구간(지수 이동 평균, "원인 확정 뒤 걷어낼 진단용"), 끊김 로그 20건, XR 세션 끝의 중앙값 · 99분위,
  GPU 타임스탬프(shadow · main · ao · bloom · tonemap · ui · total), 에디터 `GpuStatsPanel`.
- **부족한 점:** 이름 붙인 중첩 스코프, 스레드별 기록, 추적 파일(Chrome `trace.json` 또는 Tracy). Quest 실측이 아직 없어 원인을 찾을 도구가 필요합니다.
- **의존 관계:** 없음. 비동기 로딩(2위)을 할 때 스레드별 기록이 필요해집니다.
- **검증 체크리스트:**
  - [ ] 스코프 매크로가 꺼진 빌드에서 비용 0(코드 크기 · 시간).
  - [ ] `trace.json` 을 Chrome 추적 보기 · Perfetto 가 읽음, 중첩 · 스레드가 맞음.
  - [ ] 켠 상태의 프레임 비용 증가 < 0.05 ms(기본 장면).

### 3-6. 파티클 · VFX · 데칼 (6위)

- **현재 상태:** 없습니다(src · shaders 검색 0건). 디버그 선(`hdebug`)만 있습니다.
- **부족한 점:** CPU 이미터(생성률 · 수명 · 속도 · 색 · 크기 곡선), 빌보드 · 메시 파티클, 반투명 정렬(기존 2패스 반투명과의 관계), 데칼.
- **의존 관계:** 시간 곡선은 애니메이션(1위)의 커브 · 이징을 재사용합니다. 렌더 확장 지점(DEF-17 · 18)이 있습니다.
- **검증 체크리스트:** 결정적 시드로 같은 PNG, 파티클 수 상한에서 GPU 시간, Quest 오버드로 측정.

### 3-7. 텍스처 압축 (7위)

- **현재 상태:** RGBA8 sRGB 비압축 업로드, 밉은 업로드 때 블릿(`MipChain.hpp` 에 "ASTC · KTX2 를 들일 때 옮김").
- **부족한 점:** KTX2(Basis 또는 미리 압축한 ASTC · BCn) 읽기, 묶음 단계의 오프라인 압축, 장치 지원 확인.
- **의존 관계:** 업로드 경로가 비동기 로딩(2위)과 같습니다. 1GB 힙과 Quest 대역폭 예산에 직접 걸립니다.
- **검증 체크리스트:** PC BCn · Quest ASTC 각각 메모리 사용량 감소 비율, 기준 PNG 의 PSNR 하한, 지원하지 않는 장치의 대체 경로.

### 3-8. 물리 조인트 · 충돌 이벤트 (8위)

- **현재 상태:** `raycast` · `overlapSphere` · 힘 · 충격량 · Jolt `CharacterVirtual`. 충돌 레이어는 STATIC · DYNAMIC 둘입니다.
- **부족한 점:** 조인트(고정 · 경첩 · 슬라이더 · 거리), 접촉 · 트리거 콜백(센서), 스윕 · 셰이프 캐스트, 사용자 충돌 레이어 표.
- **의존 관계:** 게임플레이 이벤트(4위)로 알림을 보내면 좋습니다. 손 쥐기의 두 손 잡기가 조인트를 씁니다.
- **검증 체크리스트:** 경첩 문 각도 한계, 트리거 들어감 · 나감 한 번씩, 레이어 표로 무시한 쌍은 접촉 없음.

### 3-9. 링크된 프리팹 (9위)

- **현재 상태:** 프리팹 v5 를 꺼내면 복사합니다(GUID Fresh). 씬에 원본 링크가 남지 않습니다.
- **부족한 점:** 인스턴스 링크, 속성 덮어쓰기 기록, 중첩 프리팹, 원본을 고치면 인스턴스에 퍼짐.
- **의존 관계:** 참조 체계의 GUID · 에셋 참조 색인을 그대로 씁니다.
- **검증 체크리스트:** 원본 값을 바꾸면 덮어쓰지 않은 인스턴스만 바뀜, 덮어쓴 값은 유지, 중첩 2단 왕복.

### 3-10. 입력 확장 (10위)

- **현재 상태:** `HInputSystem` 의 동작 · 축 매핑(키 · 마우스 · XR 버튼 11개), `project.ini` 의 `input.*` 줄, XR 프로필 Oculus Touch · KHR simple, 햅틱.
- **부족한 점:** 데스크톱 게임패드(GLFW gamepad), 사용자 재지정 저장 · UI, 입력 컨텍스트 우선순위, 데드존 같은 수정자.
- **의존 관계:** 재지정 저장은 사용자 설정(3위)을 씁니다.
- **검증 체크리스트:** 가짜 장치로 게임패드 축 · 버튼 → 동작, 재지정 왕복, 컨텍스트를 바꾸면 아래 컨텍스트의 동작이 막힘.

### 3-11. 내비게이션 · AI (11위)

- **현재 상태:** 없습니다.
- **부족한 점:** 내비 메시 생성 · 경로 찾기(Recast · Detour), 간단한 상태 기계 또는 행동 트리.
- **의존 관계:** 애니메이션(1위)의 상태 기계 구조를 AI 에도 쓸 수 있습니다. 물리 정적 메시를 입력으로 씁니다.
- **검증 체크리스트:** 시험 지형에서 경로 길이 · 도달, 동적 장애물 회피, 생성 시간.

### 3-12. 오디오 버스 그래프 · 사운드 큐 (12위)

- **현재 상태:** 3D 감쇠 · 차폐 · 잔향 구역 · Steam Audio HRTF · 도플러 · 공기 흡수 · 지향성 · 가상 보이스 · 보이스 예산 · 스트리밍 · 장치 바꾸기가
  있습니다([Audio_Design.md](Audio_Design.md)). 버스 5개는 볼륨 곱셈 값이고 실제 서브믹스는 월드 그룹 하나입니다.
- **부족한 점:** 실제 버스 그래프 · 스냅숏 · 더킹, 리미터, 사운드별 동시 재생 규칙, 변형 · 랜덤 컨테이너, 버스 볼륨 저장(3위).
- **검증 체크리스트:** 더킹 곡선 RMS(루프백), 동시 재생 상한에서 가장 오래된 것이 꺼짐, 랜덤 시드 결정성.

### 3-13. 에셋 핫리로드 · 가져오기 설정 (13위)

- **현재 상태:** 에디터 · Windows 에서 `.spv` 가 바뀌면 파이프라인을 다시 만듭니다. `.gasset` 캐시는 원본 시각 · 해시로 무효화되지만 다음 읽기 때 적용됩니다.
  UID · `.meta` 파일은 만들지 않기로 정했습니다(참조 체계 D6).
- **부족한 점:** 텍스처 · 모델 · 씬 파일이 바뀌면 열린 에디터에서 다시 읽기, 에셋별 가져오기 설정(LOD · 배율 · 압축)을 어디에 둘지.
- **의존 관계:** 메시 해제(2위)가 있어야 모델을 바꿔 끼울 수 있습니다.

### 3-14. 접근성 (14위)

- **현재 상태:** 스냅 회전 각도만 있습니다.
- **부족한 점:** 자막(소리 이벤트 → 글), 글자 크기 배율(3D UI), 이동 중 비네트, 앉은 자세 높이 보정, 한 손 조작.
- **의존 관계:** 사용자 설정(3위)에 저장합니다. 글자는 [Text_System.md](Text_System.md) 를 씁니다.
