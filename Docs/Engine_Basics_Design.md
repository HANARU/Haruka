# 엔진 기본 기능 보강: 씬 관리 · 편집 기본기 · 플레이어와 입력

> **문서 지위**: 2026-10-15 에 사용자가 고른 엔진 기본 기능 다섯 가지 중 앞의 세 가지(씬 관리 · 편집 기본기 · 플레이어와 입력)의
> **결정과 구현 정본**입니다. 사용자가 설계 에이전트에게서 받아 온 제안서(UE · Unity · Godot 조사와 권장안)를 코드와 대조해
> 받을 것 · 고쳐서 받을 것 · 미룰 것을 정했고(2절), 그 결정대로 구현했습니다(3 ~ 5절).
>
> **기준 시점**: 커밋 `4cc931a` 위의 작업(2026-10-15). 나머지 두 가지(머티리얼 편집 · 독립 실행 빌드)는 이 문서의 범위가 아닙니다.
> 엔진 전체의 현재 상태는 [Engine_Specification.md](Engine_Specification.md) 를 보십시오.
>
> **갱신(2026-10-16)**: 헤드셋 확인 뒤 사용자 결정으로 "XR 에는 언제나 리그"(보이지 않는 리그 · 리그 높이 모드)를 더했습니다(2-5 · 5-2).
> 헤드셋 확인 결과는 6 · 7절에 있습니다.

## 1. 배경

작업 전의 엔진에는 다음과 같은 빈자리가 있었습니다.

- **씬**: 저장 · 불러오기 대상이 실행 폴더의 고정 파일 `scene.hscene` 하나였습니다. 지금 열린 씬이 무엇인지, 저장하지 않은 변경이
  있는지 알 수 없었고, 시작 씬은 게임 모듈 코드에 박혀 있었습니다.
- **편집**: Undo 가 트랜스폼 · 속성 · 액터 생성과 삭제까지만 되었고(리네임 · 활성 · 부모 변경 · 컴포넌트 추가와 제거는 불가),
  커맨드가 액터 포인터를 붙잡아 삭제를 되돌려도 그 전 편집 이력은 사라졌습니다. 다중 선택 · 복사 · 붙여넣기 · 복제 · 끌어 놓아
  부모 바꾸기 · 선택 대상에 화면 맞추기가 없었습니다.
- **플레이어**: Play 중에도 에디터 카메라가 화면 카메라였고, 엔진이 등록한 입력 액션이 하나도 없었습니다. 헤드셋 원점은 카메라
  위치였고, 잡기 · 던지기는 물리 API 만 있었습니다.

| 항목 | 처리 | 이유 |

| 벽에 막히는 이동(캐릭터 컨트롤러) | 미룸 | 리그 이동은 지금 벽을 통과합니다 |
| 여러 액터의 속성을 한 번에 편집 | 미룸 | 값이 다른 칸을 표시하려면 숫자 칸과 리플렉션을 다중 값 구조로 바꿔야 합니다 |

### 2-4. 뒤집은 이전 결정

2026-10-15 에 액터 생성 · 삭제 Undo 를 넣으면서 "삭제를 되돌려도 삭제 전 편집 이력은 버린다"고 정했습니다(커맨드가 포인터 기반).
이번에 모든 커맨드를 ID 기반으로 바꾸면서 그 이력이 보존됩니다. 원시 포인터를 붙잡는 커맨드가 없어져 해제된 메모리를 만질 길이
구조적으로 사라지므로 이 제안을 받았고, 보고 때 사용자에게 알렸습니다.

### 2-5. 헤드셋 확인 뒤 결정 (2026-10-16)

리그가 없는 씬(LightingProbe)을 헤드셋으로 보니 에디터 카메라 높이(바닥 위 0.3m)가 곧 눈높이라 바닥에 누운 듯 보였습니다. 사용자가
"리그를 붙여서 높이를 현실적으로 만들고 시작"하기를 원했고, 데스크톱 카메라는 지금처럼 두기로 했습니다.

| 항목 | 결정 | 근거 |
|---|---|---|
| XR 의 리그 | **XR 에는 언제나 리그가 있습니다.** 화면 카메라가 씬 리그의 머리가 아니면 엔진이 보이지 않는 리그를 붙입니다 | 사용자 결정 "XR 상태에서는 리그가 없게 하면 안 된다" |
| 보이지 않는 리그의 자리 | 카메라 아래 바닥(카메라에서 아래로 쏜 광선이 처음 만나는 메시 윗면). 수평 위치 · 요는 카메라를 따르고, 아래에 아무것도 없으면 카메라 위치 | 사용자 선택(권장안). 카메라를 공중에 두고 Play 해도 바닥에 섭니다 |
| 리그 높이 | 실제 키(OpenXR 바닥 기준 공간 LOCAL_FLOOR)와 고정 눈높이(값을 정함, 0.5 ~ 2.5m) 두 모드. 씬 리그는 컴포넌트 값, 보이지 않는 리그는 프로젝트 설정 `xr.height` · `xr.eyeHeight` | 사용자 요청 "리그의 길이를 임의로 정할 수 있게, OpenXR 에서 읽어오는 값 활용". Unity XR Origin 의 Floor · Device 모드(Camera Y Offset)와 같은 구분입니다. OpenXR 에는 사용자 키 값이 따로 없고, 바닥 기준 공간의 머리 높이가 그 역할을 합니다 |

## 3. 씬 관리 (1단계)

### 3-1. 설정 파일

| 파일 | 위치 · 성격 | 키 |
|---|---|---|
| `assets/project.ini` | 프로젝트 폴더, 버전 관리함. 시작할 때 한 번 읽음 | `startScene`(논리 경로), `input.action.이름` · `input.axis.이름`(5-5), `xr.height` · `xr.eyeHeight`(5-2, 2026-10-16) |
| `Config/editor_state.txt` | 실행 폴더, 버전 관리하지 않음(`.gitignore`) | `lastScene` |

에디터를 열면 `lastScene` 이 있고 파일이 남아 있으면 그 씬을, 아니면 `startScene` 을, 둘 다 없으면 빈 씬을 엽니다. 시작 씬은 이제
에디터가 열고, `DefaultGameModule::onStart` 는 비었습니다.

### 3-2. 열린 씬과 변경 여부(`SceneDocument`)

- 씬은 프로젝트 폴더의 `assets/scenes/` 아래 논리 경로로 열고 저장합니다. 이름 없는 새 씬은 "Untitled" 입니다.
- 변경 여부는 저장한 순간의 Undo 상태 표지(`HCommandStack::stateToken`)와 지금 표지를 비교해 정합니다. 커맨드마다 쌓을 때 받은
  일련번호를 표지로 쓰므로, 되돌린 뒤 다른 편집을 같은 개수만큼 쌓아도 깨끗한 것으로 착각하지 않습니다. 이력을 비우면 새 표지가
  나오고, 64단계를 넘어 밀려난 커맨드의 번호도 기억해 저장 시점으로 돌아갈 수 없게 되면 변경으로 남습니다.
- Play 를 시작할 때 변경 여부를 고정했다가, Stop 이 월드를 되돌리고 이력을 비운 뒤 그 값으로 돌려놓습니다.
- 제목 표시줄과 상태바에 `이름.hscene*` 처럼 표시합니다.

### 3-3. 저장 · 열기 · 대화상자

- **원자적 저장**: 같은 폴더의 임시 파일(`.tmp`)에 쓰고 닫은 뒤 원래 파일로 바꿉니다(`hfile::writeAtomic`). 쓰다가 실패해도 원래 파일은
  그대로입니다.
- **메뉴 · 단축키**: File 의 New Scene(Ctrl+N) · Open Scene(Ctrl+O) · Save Scene(Ctrl+S) · Save Scene As(Ctrl+Shift+S), 툴바의 Save · Open.
- **대화상자**: 화면 전체를 덮는 HSlate 모달입니다. 버튼 동작은 프레임 끝에 실행하고, 대화상자가 열린 동안 뷰포트 · 기즈모 키 입력을
  막습니다.
  - Open Scene: `assets/scenes/` 의 씬 목록.
  - Unsaved Changes: 새 씬 · 다른 씬 열기 · 창 닫기 전에 변경이 있으면 Save · Don't Save · Cancel 을 묻습니다. 창 닫기는 엔진 루프가
    가로채 묻습니다.
  - Save Scene As: `assets/scenes/` 아래 이름(영문자 · 숫자 · 공백 · `-` `_`, 폴더는 `/`). 잘못된 이름이면 입력한 글 그대로 다시 묻고, 이미
    있는 파일이면 Replace 를 확인합니다.
- Play 중에는 저장 · 열기 · 새 씬을 막고 경고합니다(Stop 하면 Play 월드가 버려지기 때문).
- 콘텐츠 브라우저에 SCENES 항목이 생겼고, 지금 열린 씬을 강조합니다. 클릭하면 엽니다.

### 3-4. 옛 형식 에셋

`LightingProbe.hscene` 은 v4 로(다시 저장 전후 뷰포트는 통계 글자 가장자리 18픽셀 말고는 같음), `AudioProbe.hprefab` 은 v3 으로 다시
저장했습니다(설명 주석 두 줄은 손으로 되살림).
읽기 쪽 호환(v3 이하 씬, v1 · v2 프리팹)은 그대로 둡니다.

## 4. 편집 기본기 (2단계)

### 4-1. ID 기반 Undo 커맨드

모든 커맨드(`EditorCommands.hpp`)는 액터를 ID 로 기억하고 실행할 때마다 `World::findById` 로 찾습니다. 없으면 아무것도 하지 않습니다.
컴포넌트는 타입 이름과 같은 타입 안의 순번으로 찾습니다.

| 커맨드 | 대상 |
|---|---|
| `SetTransformCmd` | 트랜스폼(기즈모 · 숫자 칸) |
| `RenameActorCmd` · `SetActiveCmd` | 이름 · 활성(아웃라이너 눈 버튼 포함) |
| `ReparentCmd` | 부모와 형제 순서, 이전 · 이후 로컬 트랜스폼 |
| `ComponentEnabledCmd` · `ComponentPropsCmd` | 컴포넌트 켜기 · 속성 |
| `ComponentPresenceCmd` | 컴포넌트 추가 · 제거(블록 글로 떠 두었다가 같은 자리로 되살림) |
| `ActorPresenceCmd` | 액터 생성 · 삭제(서브트리를 원래 ID · 부모로 되살림) |
| `CompositeCmd` | 여러 커맨드를 한 번에(그룹 이동 · 여러 액터 붙여넣기 · 끌어 놓기) |

그래서 "편집 → 삭제 → 삭제 되돌리기 → 편집 되돌리기"가 이어집니다.

### 4-2. 다중 선택

- `EditorContext::selected` 는 주 선택(마지막으로 고른 것), `selection` 은 전체 선택입니다.
- 아웃라이너: 클릭은 하나만, Ctrl+클릭은 넣고 빼기, Shift+클릭은 주 선택부터 그 행까지. 뷰포트: Ctrl+클릭은 넣고 빼기.
- 디테일 패널은 주 선택만 보여 주고 머리에 "N actors selected (showing the last one)" 배지를 둡니다. 뷰포트는 다른 선택 액터의 상자도 그립니다.
- 기즈모는 주 선택에 그리고, 끄는 동안 나머지 액터가 주 선택 피벗을 기준으로 같은 변환을 받습니다(`hxform::followPivot`). 부모와 자식이
  함께 선택되면 부모만 움직입니다. 놓으면 `CompositeCmd` 하나로 쌓여 한 번에 되돌아갑니다.

### 4-3. 복사 · 붙여넣기 · 복제 · 삭제

- Ctrl+C 는 선택한 서브트리들을 씬 형식 글로 OS 클립보드에 씁니다. 첫 줄 `#HARUKA_ACTORS 1`, 둘째 줄 `#ROOT_PARENTS` 뒤에 루트마다 원래 부모
  ID 를 적습니다. 다른 프로그램에서 복사한 글이면 붙여넣지 않고 경고합니다.
- Ctrl+V 는 원래 부모가 남아 있으면 그 아래, 없으면 루트에 같은 트랜스폼으로 붙여넣습니다. Ctrl+D 는 클립보드를 거치지 않는 같은 동작입니다.
  붙여넣은 루트 이름은 Unity 처럼 "Name (1)", "Name (2)" 로 매깁니다.
- Delete 는 선택 전체를 지웁니다. 모두 커맨드 하나로 되돌아갑니다.

### 4-4. 부모 바꾸기

- 에디터에서 부모를 바꾸면 월드 자세를 유지하도록 로컬 트랜스폼을 다시 계산합니다(`hxform::localForWorld`, DEF-53 의 규칙).
- 아웃라이너에서 행을 끌어 다른 행에 놓으면 그 아래로, 목록의 빈 곳에 놓으면 루트로 옮깁니다. 끄는 동안 놓을 자리를 표시하고,
  자기 자신이나 자손 아래로는 옮기지 않습니다(경고). 선택된 행을 끌면 선택 전체가 함께 옮겨집니다.

### 4-5. 화면 맞추기(F)

선택한 액터들의 월드 바운드를 합친 구를 화면에 맞춥니다. 거리 = 반지름 / sin(세로 · 가로 시야각 중 작은 쪽의 절반) × 1.1(가장자리 여유)이고, 카메라가
짧게 이동합니다(Edit 메뉴 Frame Selected).

### 4-6. 프리팹 v3

`.hprefab` v3 은 서브트리를 씬 블록으로 저장하고 첫 블록이 루트입니다. Save as Prefab 이 자식까지 담고, 꺼낼 때 계층이 그대로 생깁니다.

## 5. 플레이어와 입력 (3단계)

### 5-1. 컴포넌트

| 컴포넌트(에디터 라벨) | 역할 |
|---|---|
| `XrRigComponent`(XR Rig) | 바닥의 플레이어 원점. 자식의 추적 자세가 이 액터 기준 로컬로 들어갑니다. `height`(tracked · fixed)와 `eyeHeight`(기본 1.7m, 2026-10-16) |
| `TrackedPoseComponent`(Tracked Pose) | 머리 · 왼손 · 오른손 자세를 로컬 트랜스폼으로 씀. XR 입력이 있을 때만 바꿉니다. `showDebug` 면 손의 축 · 가리키는 선을 그립니다(예전에 에디터가 카메라 원점 기준으로 그리던 표시, 손 추적 컴포넌트가 하나도 없을 때만 에디터가 예전처럼 그림) |
| `RigLocomotionComponent`(Locomotion) | 기본 이동. `moveSpeed` 2m/s, `snapTurn` 45°, `flying`, `lookSensitivity` 0.15°/px |
| `GrabbableComponent`(Grabbable) | 잡을 수 있는 액터. `throwable` |
| `GrabInteractorComponent`(Grab Hand) | 손 액터에서 그립으로 잡고 놓음. `radius` 0.12m |

표준 구성은 `assets/prefabs/XrPlayer.hprefab`(리그 + Head 카메라 + 두 손)이고, 시연 씬은 `assets/scenes/XrDemo.hscene`(탁자 위 잡을 수 있는
상자 둘 · 공 하나)입니다.

### 5-2. 카메라와 헤드셋 원점

- 편집 중 화면 카메라는 에디터 카메라이고, Play 중에는 켜진 첫 primary 씬 카메라입니다. 없으면 에디터 카메라입니다(`World::getActiveCamera`).
- XR 에는 언제나 리그가 있습니다(2026-10-16).
  - 화면 카메라가 씬 리그의 Head(Tracked Pose[Head] + 부모가 XR Rig)이면 엔진이 프레임마다 그 리그를 헤드셋 원점으로 넘깁니다
    (`CameraComponent::setXrRig`).
  - 화면 카메라에 켜진 Tracked Pose[Head] 가 있지만 부모가 XR Rig 가 아니면, 그 부모(없으면 월드 원점)를 리그처럼 원점으로 씁니다
    (2026-11-06, DEF-144, `hxr::chooseOrigin` · `CameraComponent::setXrTrackedParent`). Unity 의 Tracked Pose Driver · UE 의 카메라와 같은
    규칙입니다. 예전에는 보이지 않는 리그를 붙여, 머리 추적이 이미 옮긴 카메라 위치 · 요를 원점으로 다시 써서 두 번 적용됐습니다(30° 돌면
    60°). 같은 카메라에는 "XR rig: camera … tracks the head without an XR Rig parent" 로그가 한 번 남습니다.
  - 아니면(머리 추적이 없거나 꺼짐) 보이지 않는 리그를 붙입니다(`CameraComponent::setXrImplicitRig`). 이 카메라로 XR 을 처음 볼 때 카메라 아래 바닥을 한 번
    찾고(`hxr::floorBelow`: 켜진 액터의 로컬 바운드 합집합에 아래 방향 광선-OBB, 카메라를 감싼 바운드와 카메라 자신 · 자식은 건너뜀),
    그 뒤에는 카메라를 따라 같은 거리 아래에 둡니다. 아래에 아무것도 없으면 카메라 위치입니다. 로그에 "XR rig: none in the scene;
    standing on the floor … below the camera"가 남습니다.
- 높이 모드에 따라 공간을 고릅니다(`XrSystem::setRigSpace`). 실제 키면 바닥 기준 공간(LOCAL_FLOOR, `XR_EXT_local_floor`), 고정 눈높이면
  LOCAL 공간에 눈높이를 더합니다. 실제 키인데 런타임에 바닥 공간이 없으면 눈높이 값으로 갑니다. 더할 높이는 입력이 아니라 XR 시스템의
  공간 선택에서 읽으므로(`XrSystem::rigLift`), 시스템 메뉴가 떠 초점을 잃은 동안에도 원점이 내려가지 않습니다.
- XR 세션이 없으면(데스크톱 · 스테레오 흉내) 예전처럼 카메라 위치 + 요입니다.

### 5-3. 이동

- VR: 왼쪽 스틱(MoveX · MoveY)으로 머리가 보는 방향 기준 이동, 오른쪽 스틱(TurnX)으로 머리 자리를 중심으로 45° 스냅 회전. 스틱을 70% 넘게
  기울이면 한 번 돌고, 30% 아래로 돌아와야 다시 돕니다.
- 데스크톱 Play: WASD 이동, 뷰포트에서 오른쪽 버튼을 누른 채 끌면 둘러보기(좌우는 리그를 머리 둘레로, 위아래는 머리만 숙임). 플레이어를
  조종하는 동안 에디터 기즈모 키는 꺼집니다.
- `flying` 이 꺼져 있으면 리그의 수평면 위로만 걷고, 켜면 보는 방향 그대로 움직이며 E/Q(MoveUp)로 오르내립니다. 벽에 막히지 않습니다.

### 5-4. 잡기 · 던지기

- 그립(GrabLeft · GrabRight)을 쥐는 순간 손에서 반지름 안의 가장 가까운 Grabbable 을 잡습니다. 거리는 액터 바운드(없으면 위치)까지 잽니다.
- Dynamic 강체는 잡는 동안 같은 바디를 Kinematic 으로 바꿔(`PhysicsSystem::setMotionKinematic`, Jolt `SetMotionType`) 손 기준 자리를 따라가고,
  놓으면 Dynamic 으로 돌아오면서 손 속도(리그 회전을 곱해 월드로 바꾼 선속도 · 각속도)를 받습니다. 바디를 다시 만들지 않으므로 잡은 동안
  속성을 확정해도 그대로입니다.
- 강체가 없는 소품은 손을 따라가다 놓은 자리에 남습니다. 다른 손이 잡으면 넘겨받고, 잡힌 액터를 끄거나 지우면 손이 놓습니다.
- 잡을 때 짧은 진동(0.6, 40ms), 놓을 때 더 약한 진동(0.3, 20ms)을 보냅니다.

### 5-5. 입력

- **축** = 묶인 XR 축 중 절댓값이 가장 큰 값 + 키 축(양 · 음 키, -1 ~ 1) + 마우스 축(이동량 × 배율). 이동 코드가 길이 1 로 자릅니다.
- **마우스 축**은 Play 중 뷰포트 오른쪽 버튼 끌기 양입니다. 에디터가 넣고 엔진이 프레임 끝에 비웁니다.
- **액션**에 XR 트리거 · 그립을 버튼으로 묶을 수 있습니다(0.5 에서 끊음). `held(이름)` 로 지금 눌림을 묻습니다.
- **햅틱**: `HInputSystem::haptic(손, 세기, 초)` 을 엔진이 XR 의 진동 액션(`xrApplyHapticFeedback`)으로 보냅니다.
- **설정 줄 문법**(`assets/project.ini`): `input.action.이름 = 소스, 소스`, `input.axis.이름 = 소스, 소스`. 소스는 `key:W` · `key:Space` · `key:F5` ·
  `xr:left.grip` · `xr:right.a` · `xr:right.trigger`(액션), `keys:W/S` · `xr:left.stick.y` · `xr:left.trigger` · `mouse:x` · `mouse:y*0.5`(축).
  틀린 줄은 경고하고 그 이름의 기존 바인딩을 바꾸지 않습니다. 설정에 입력 줄이 없으면 엔진 기본 바인딩(`HInputSystem::defaultBindings`,
  저장소의 `project.ini` 와 같은 8줄)을 씁니다.
