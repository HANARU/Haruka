# 에디터 실기 체크리스트 — 종합 오류 검출

작성 2026-10-02. 에디터를 열기 **전에** 무엇을 어떤 순서로 확인할지 정해 두는 문서입니다. 한 세션에서
(1) 결함 재현으로 수정 전 기준선을 남기고, (2) 기능 전반이 깨지지 않았는지 회귀를 점검합니다. 결과는
마지막 절의 표에 적습니다. 수정을 마친 뒤 같은 표로 다시 확인합니다.

**표기.** [사람] 은 사람이 직접 해야 하는 항목입니다(손 조작의 감각, 눈·귀 판단, 자동 조작으로는 재현이
의심스러운 것). [자동] 은 computer-use 로 진행할 수 있는 항목입니다. 표시가 없으면 어느 쪽이든 됩니다.

**자동 조작의 한계(2026-10-02 실측).** 자동으로 점검할 때는 아래를 지킵니다.

- **Claude 데스크톱 앱 창이 화면 일부를 덮습니다.** 항상 위에 있는 레이어드 창이라 스크린샷에는 가려져 보이지
  않지만 입력은 받습니다(2026-10-02 에는 물리 좌표 (1372,20)~(1908,748)). 그 영역의 클릭과 커서 이동은 에디터에
  가지 않습니다. 시작 전에 `WindowFromPoint` 로 범위를 재고, `SetWindowPos` 로 에디터 창을 그 밖에 둡니다
  (예: 0,0,1368,1032). 지난 DEF-73 ~ DEF-75 는 이것 때문에 생긴 착시였습니다.
- **커서는 두 번 옮깁니다.** 엔진은 이동 이벤트로 받아 둔 커서 위치를 씁니다. 목표 지점으로 옮긴 뒤 1~2px 더
  옮기고 누릅니다.
- **클릭과 키는 한 프레임보다 길게 누릅니다(수정 전 빌드에만 해당).** 에디터가 상태를 프레임마다 읽어서(DEF-82),
  `left_click` 이나 `key` 처럼 바로 떼는 입력은 사라집니다. 클릭은 "누름 → 0.15초 → 뗌", 키는 `hold_key` 0.15초 이상으로
  보냅니다. DEF-82 를 고친 빌드(2026-10-02)부터는 바로 떼는 입력도 그대로 들어갑니다.
- **Esc 는 자동 조작 계층이 가로채 에디터에 오지 않습니다**(Input 로그에 PRESS 가 남지 않음). Esc 항목은 [사람].
  오른쪽 Ctrl 은 키 이름 `rctrl` 로 보낼 수 있습니다.
- **`open_application` 으로 에디터를 앞으로 가져오지 마십시오.** 새 인스턴스가 뜹니다. 제목 표시줄을 한 번 누릅니다.
- 휠은 한 프레임에 합쳐집니다. 뷰포트에서 왼쪽 버튼을 누른 채 움직이면 카메라가 팬하므로, 측정 전후로 뷰가
  그대로인지 확인합니다. 아웃라이너·Output Log 는 한 프레임의 휠을 크기와 무관하게 3줄로 세므로, `scroll` 몇 칸이
  한 프레임에 합쳐지면 3줄만 움직입니다. 디테일·콘텐츠 브라우저·GPU Stats 는 칸 수만큼 움직입니다(2026-10-03 부터).
- **합성 키 누름은 OS 자동 반복을 만들지 않습니다(2026-10-03 확인).** `hold_key` 로 백스페이스를 1.6초 눌러도 반복
  이벤트가 없습니다. 키 반복(DEF-58)은 에디터 창 핸들에 `PostMessage` 로 `WM_KEYDOWN` 을 보내 확인합니다. 첫 누름은
  lParam `0x000E0001`, 반복은 이전 상태 비트가 선 `0x400E0001`, 뗌은 `WM_KEYUP` `0xC00E0001` 입니다(백스페이스 스캔코드
  0x0E). 창 핸들로 보내므로 포커스가 다른 창으로 가도 그 창에는 입력이 가지 않습니다.

## 2. 결함 재현 — 수정 전 기준선

근거는 2026-10-02 정적 검출(코드 대조 세 갈래)입니다. 각 줄의 "지금" 은 코드가 말하는 현재 동작이고,
"고친 뒤" 는 수정 후 확인할 동작입니다. 결함 설명과 위치는 [Core_Defects_Task_Spec.md](Core_Defects_Task_Spec.md)
를 봅니다. 값이 바뀌는 항목(DEF-77 등)은 0-3 백업이 있는 상태에서만 합니다.

### 2-A. 자동 조작 진단 — DEF-73 ~ DEF-75 판정의 전제

엔진은 마우스 위치를 OS 에 묻지 않고 커서 이동 콜백이 받아 둔 값(`GlfwWindow::lastMouseX`)을 씁니다.
자동 조작의 커서 이동이 이 콜백을 부르지 못하면, 클릭이 직전 위치에 떨어집니다. 그러면 DEF-73 ~ DEF-75 의
관찰(아웃라이너 행 재클릭에 의한 선택 해제, 뷰포트 재픽, 숫자 칸 미진입)이 모두 설명됩니다.

| # | 조작 | 판정 |
|---|---|---|
| 2-A1 | [자동] 진단 로그를 넣은 빌드에서 누름·뗌마다 "받아 둔 위치" 와 `glfwGetCursorPos` 의 실제 위치를 함께 남깁니다. 아웃라이너 행 클릭 → 디테일 숫자 칸 클릭 순서로 합니다 | 두 위치가 다르면 자동 조작의 산물입니다. 같은데도 증상이 나오면 엔진 결함입니다 |
| 2-A2 | [사람] 같은 순서를 손으로: 아웃라이너 행 클릭 → 디테일 Location X 클릭 → 플레이 중 디테일 토글 클릭 | 손으로는 선택이 유지되고, 숫자 칸이 입력 모드가 되고, 토글이 바뀌면 DEF-73 ~ DEF-75 를 닫습니다 |

**2-A 결과(2026-10-02):** 자동 조작의 산물로 판정해 DEF-73 ~ DEF-75 를 닫았습니다. 디테일 클릭 때 실제 커서는
(1741,208)인데 받아 둔 위치는 직전 클릭의 (55,246)이었고, 그 클릭이 아웃라이너 같은 행을 다시 눌렀습니다.
또 그 영역은 Claude 앱 창이 덮고 있었습니다. 에디터 창을 그 밖으로 옮기자 같은 클릭이 정상으로 입력 모드에
들어갔습니다. 2-A2 는 사람이 한 번 확인해 주면 됩니다.

## 3. 기능 회귀 점검

각 항목은 "조작 → 기대 결과" 입니다. 실패하면 5절 표에 적고, 결함 문서에 없는 것이면 새 번호를 받습니다.

### 3-1. 아웃라이너
