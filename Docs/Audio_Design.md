# 오디오 설계 — 사운드 기초 정리

작성 2026-10-02. 로드맵에서 합의한 순서(PRIM 직렬화 → **사운드 기초** → 종합 오류 검출 → VR)의
두 번째 항목입니다. 오디오는 그동안 뼈대만 있었고, 재생 규칙과 청취자에 결함이 있었습니다.
이 문서는 고친 내용, 지금의 규칙, 검증 방법, 남은 일을 정리합니다.

---

## 1. 구조

| 요소 | 위치 | 역할 |
|---|---|---|
| miniaudio 0.11.21 | `CMakeLists.txt`(FetchContent) | `ma_engine` 하나, 48 kHz 스테레오. 출력 장치는 `AudioSystem` 이 직접 만들어 엔진에 연결합니다(2026-10-16, 8절) |
| 구현부 번역 단위 | `src/audio/MiniaudioImpl.cpp` | miniaudio·stb_vorbis 구현만 담습니다(9만 줄 넘는 구현을 따로 컴파일) |
| `AudioSystem` | `src/audio/AudioSystem.*` | 엔진 모듈. 사운드 생성, 매 틱 위치·설정 반영, 청취자 갱신, 일시정지 |
| `AudioComponent` | `src/components/AudioComponent.*` | 파일·볼륨·Loop·AutoPlay·3D 설정. 활성 변화에 따라 멈춤·재생 |
| `AudioAttenuationSettings` | `src/audio/AudioAttenuation.*` | 3D 설정 값과 씬 파일 텍스트 형식(`AUDIO_3D`) |

- **지원 형식**: WAV·FLAC·MP3(miniaudio 내장), OGG Vorbis(stb_vorbis). 예전에는 콘텐츠 브라우저가
  `.ogg` 를 보여 주는데도 디코더가 없어 불러오기가 항상 실패했습니다. stb_vorbis 는 miniaudio 저장소의
  `extras/` 에 있는 것을 써서 miniaudio 태그와 버전이 함께 고정됩니다. 이 파일은 `/W4` 에서 경고를
  70건 넘게(좁히는 변환 C4244 등) 내므로 `MiniaudioImpl.cpp` 의 그 include 구간에서만 경고를 끕니다.
- **월드 그룹**: 월드 사운드는 전부 `ma_sound_group` 하나에 붙습니다. 그룹은 공간화가 꺼져 있고(섞인
  소리를 다시 감쇠하지 않음), 피치도 끕니다(`MA_SOUND_FLAG_NO_PITCH`). 피치가 켜져 있으면 그룹이 섞인
  소리 전체를 배율 1 로 리샘플링하느라 연산을 쓰고, 한 프레임 늦게 내보내서 멈춘 소리의 마지막 샘플이
  다음 블록 첫머리에 남았습니다(오디오 테스트 5절이 잡았습니다).
- **사운드 생성 시점**: 플레이 중에 `AudioSystem::tick` 이 컴포넌트를 처음 만날 때 만듭니다. 에디터
  상태에서는 사운드가 없습니다. 불러오기는 `MA_SOUND_FLAG_ASYNC` 이지만 miniaudio 가 디코더 초기화까지
  기다렸다 돌아오므로(`WAIT_INIT` 강제), 없는 파일과 모르는 형식은 그 자리에서 실패하고 이유가 로그에
  남습니다(`failed to load '<경로>': <miniaudio 설명>`).

## 2. 재생 규칙

| 상황 | 동작 | 예전 |
|---|---|---|
| Play 시작 | 다음 틱에 사운드를 만들고 AutoPlay 면 재생합니다. 지난 플레이에서 실패한 파일은 다시 시도합니다. | 같음 |
| Pause | 월드 그룹을 멈춥니다. 그룹 아래 사운드는 믹싱에서 읽히지 않아 재생 위치가 그대로 멈춥니다. | **소리가 계속 났습니다** |
| Resume | 그룹을 다시 시작합니다. 멈춘 자리에서 이어집니다. | — |
| Stop(에디터) | 월드를 스냅숏으로 되돌리면서 사운드가 정리됩니다. Pause 상태에서 Stop 해도 다음 Play 는 정상입니다(`onEndPlay` 가 그룹 정지를 풉니다). | — |
| 액터 `setActive(false)`, 부모 비활성, 컴포넌트 끄기 | 멈추고 처음으로 되감습니다(`onDisable`). | **소리가 계속 났습니다** |
| 다시 켜기 | AutoPlay 사운드를 처음부터 재생합니다(`onEnable`, Unity 의 Play On Awake 와 같은 규칙). | — |
| `AudioComponent::stop()` | 멈추고 되감습니다. 다음 `play()` 는 처음부터입니다. | 일시정지처럼 이어서 재생했습니다 |
| 디테일 패널에서 값 변경 | 볼륨·Loop·3D 설정을 매 틱 사운드에 반영하므로 플레이 중에도 바로 적용됩니다. | Loop 는 만들 때만 적용됐습니다 |
| 엔진 종료 | `AudioSystem::shutdown` 이 남은 사운드를 정리하고 컴포넌트의 포인터를 비운 뒤 엔진을 닫습니다. | World 가 `onDestroy` 없이 해제돼 사운드가 정리되지 않았습니다 |

일시정지는 엔진 모듈의 새 훅으로 전달합니다. `IEngineModule` 에 `onEndPlay()` 와
`onPauseChanged(bool)` 을 추가했고, `Engine::run` 이 상태 전이를 감지해 부릅니다. 일시정지 통지는
시작·끝 처리 **뒤**에 보냅니다. Pause 상태에서 곧바로 Stop 하면 끝 처리가 먼저 소리를 멈추므로, 뒤따르는
재개 통지가 남은 소리를 다시 들려주지 않습니다. 일시정지 동안 Engine 은 `tick` 을 부르지 않지만 믹싱은
오디오 스레드에서 계속 돌기 때문에, 모듈이 직접 멈춰야 합니다.

## 3. 3D 설정과 청취자

### 3-1. 청취자

활성 카메라(에디터에서는 에디터 카메라)의 위치와 방향을 매 틱 넘깁니다. 예전에는 **위치만** 넘겨서
청취자가 늘 -Z 를 보고 있었고, 카메라를 돌려도 소리의 좌우가 바뀌지 않았습니다. 방향은
`CameraComponent::forward()` 하나에서 나오며, 렌더(`viewMatrix`)와 에디터 카메라 이동도 같은 함수를
씁니다. 좌표계는 오른손, +Y 위, yaw=pitch=0 이면 -Z 를 보고 오른쪽이 +X 입니다(miniaudio 기본값과 같음).

miniaudio 는 방향 × 위 벡터로 청취자의 오른쪽을 정합니다. 카메라 자세가 액터 회전이 된 뒤로(DEF-21, 2026-10-04)
롤이 있을 수 있으므로 월드 +Y 가 아니라 카메라의 위 벡터(`CameraComponent::up()`)를 넘깁니다.

**XR 세션 중에는 머리 자세를 따릅니다(2026-10-15).** 헤드셋을 쓰면 카메라는 XR 원점(위치 + 요)일 뿐이라,
카메라를 따르면 고개를 돌려도 소리의 좌우가 바뀌지 않습니다. XR 세션이 입력을 받는 동안(FOCUSED) Engine 이
매 프레임 `카메라 XR 원점 × 머리 자세`(손 자세와 같은 기준)를 `AudioSystem::setListenerPose` 로 넘기고, 세션이
멈추거나 머리 추적을 잃으면 `clearListenerPose` 로 다시 카메라를 따르게 합니다. AudioSystem 은 입력 모듈을
모르고 자세만 받으므로 장치 없는 테스트로 검산합니다.

패닝은 miniaudio 의 단순 모델입니다. 스테레오 출력에서는 스피커를 정확히 좌우(SIDE_LEFT = (-1, 0, 0),
SIDE_RIGHT = (+1, 0, 0))에 둡니다(`ma_get_default_channel_map_for_spatializer` 의 스테레오 특례). 음원 방향과 스피커 방향의
내적을 0~1 로 옮긴 값이 채널 게인이고, 반대편 채널은 0.2 아래로 내려가지 않습니다. 그래서 정면 · 뒤 · 바로 위 음원은
두 채널 모두 0.5, 바로 오른쪽 음원은 오른쪽 1 · 왼쪽 0.2 입니다. **앞뒤와 위아래를 전혀 구분하지 못합니다.** HRTF 가 켜지면
(2026-11-06, 9-6: 기본은 XR Play 동안) 패닝을 끄고 HRTF 가 방향을 냅니다. 이 절의 값은 HRTF 가 꺼진 때의 값입니다.

> **정정(DEF-166, 2026-11-06).** 예전 이 절은 스피커를 앞쪽 ±45°(FL · FR)로 보고 "정면 음원은 채널마다 0.854, 앞뒤 구분은
> 거의 없음"이라고 적었습니다. miniaudio 의 방향 표에는 FL · FR 이 있지만, 엔진 청취자는 스테레오일 때 SIDE_LEFT/RIGHT 를 씁니다.
> 오디오 테스트 2-2절이 실측으로 값을 고정합니다(정면 0.500/0.500, 뒤 0.500/0.500, 오른쪽 0.200/1.000, 위 0.500/0.500).

### 3-2. 감쇠 설정

| 디테일 행 | 필드 | 기본값 | 의미 |
|---|---|---|---|
| Spatialize | `spatialize` | 켜짐 | 끄면 2D: 위치와 무관하게 감쇠·패닝 없이 들립니다(음악·UI용). 끄면 아래 행이 숨겨집니다. |
| Attenuation | `model` | Inverse | 거리 감쇠 곡선(아래 식) |
| Min Distance | `minDistance` | 1 m | 이 거리 안에서는 줄지 않습니다 |
| Max Distance | `maxDistance` | 100 m | 이 거리 밖에서는 더 줄지 않습니다(Linear 는 여기서 0) |
| Rolloff | `rolloff` | 1 | 곡선 기울기. 0 이면 거리 감쇠가 없습니다 |

d 는 [Min, Max] 로 자른 거리입니다.

- Inverse: `min / (min + rolloff·(d − min))`
- Linear: `1 − rolloff·(d − min) / (max − min)`, 0 아래는 0
- Exponential: `(d / min)^(−rolloff)`

**설계 판단 두 가지.**

1. **UE 이름(Inner Radius / Falloff Distance)을 쓰지 않았습니다.** 라이트는 "UE 명칭만" 따랐지만, 그때는
   이름과 뜻이 맞았습니다. UE 의 Falloff Distance 는 "그 밖은 무음"을 뜻하는데, miniaudio 의 Inverse·
   Exponential 은 Max Distance 밖에서 줄지 않고 그 값에 머뭅니다. 이름만 빌리면 뜻이 어긋나므로
   실제 의미대로 Min/Max Distance(OpenAL·Unity 와 같은 이름)를 씁니다.
2. **miniaudio 의 `none` 모델은 목록에 두지 않았습니다.** `none` 은 거리 감쇠뿐 아니라 좌우 패닝까지 꺼서
   Spatialize 를 끈 것과 같습니다. 방향은 살리고 거리 감쇠만 없애려면 Rolloff 를 0 으로 둡니다.

Min 과 Max 는 서로를 넘지 못합니다(간격 0.01 m). miniaudio 는 min ≥ max 이면 감쇠를 통째로 끕니다.

## 4. 씬 형식

```
AUDIO:assets/audio/Test_BeepLoop.wav
AUDIO_VOL:1 1 1 1          (볼륨, Loop, AutoPlay, 컴포넌트 enabled)
AUDIO_3D:1 inverse 1 100 1 (spatialize, 모델 이름, min, max, rolloff)
```

- `AUDIO_3D` 는 2026-10-02 에 추가했습니다. `AUDIO_VOL` 끝에 토큰을 덧붙이지 않고 새 키로 넣었습니다.
  LIGHT 줄이 위치 기반 확장을 세 번 거치며 취약해진 것을 되풀이하지 않기 위해서입니다. 그래서 이 줄은
  토큰 다섯 개를 정확히 요구하고, 나중에 값이 늘면 다른 키로 추가합니다.
- 모델은 순번이 아니라 이름(`inverse`/`linear`/`exponential`)으로 씁니다(DEF-44 의 순번 기록 문제를 피함).
- 값이 깨졌으면(토큰 수, 모르는 모델, 0 < min < max 위반, 음수 rolloff, NaN·inf) 기본 설정으로 두고
  `[Scene]` 오류를 남깁니다. 소리 자체는 버리지 않습니다(PRIM_MAT 과 같은 규칙).
- 옛 파일에는 이 줄이 없어 기본값이 쓰입니다. 예전 동작과의 차이는 Max Distance 가 무한에서 100 m 로
  바뀐 것뿐인데, Inverse 기본 곡선에서 100 m 의 게인이 0.01(-40 dB)이라 들리는 차이는 없습니다.
- 씬 헤더는 v3 그대로입니다. 줄이 없으면 기본값이고, 옛 엔진은 모르는 키를 건너뛰기 때문입니다.
- **[2026-11-06]** 오디오 블록에 `occlusion` 키(차폐 설정, `enabled lowPassHz volume smoothTime radius`, 9-4)와 `reverbSend` · `reverbReach`(9-5)가
  생겼습니다. 없으면 기본값이고, 깨졌으면 기본으로 두고 `[Scene]` 오류를 남깁니다. 잔향 구역은 `ReverbZoneComponent` 블록입니다(9-5).
- **[2026-10-14 갱신]** 씬 형식은 2026-10-14 에 v4 로 바뀌어 컴포넌트를 COMPONENT 블록의 이름 붙은 값으로 씁니다(DEF-22). v3 파일도 계속 읽습니다. `AUDIO:` · `AUDIO_VOL:` · `AUDIO_3D:` 는 오디오 블록의 `file` · `volume` · `loop` · `autoPlay` · `attenuation` 이 됐고, `attenuation` 의 텍스트 형식은 `AUDIO_3D:` 와 같습니다.

## 5. 검증

### 5-1. 오디오 테스트 (`HarukaAudioTest`, 2026-11-07 기준 191항목)

출력 장치 없는 miniaudio 엔진(`noDevice`)에서 출력 샘플을 직접 당겨 숫자로 검산합니다. 소리 결함은 화면에
보이지 않고, 좌우 부호가 뒤집힌 것 같은 결함은 귀로 들어도 놓치기 쉽기 때문입니다. 재생 위치는 프레임
i 의 값이 `i·1e-5` 인 32비트 float 램프 파일로 읽습니다(공간화를 끄면 출력 값이 곧 재생 위치).

| 절 | 확인하는 것 |
|---|---|
| 1 | 장치 없는 엔진 생성과 출력 당기기 |
| 2 | 청취자 방향: +X 음원이 정면(-Z)일 때 오른쪽, 뒤돌면 왼쪽, 음원 쪽을 보면 좌우 같음 |
| 2-1 | XR 머리 자세: 넘긴 자세의 방향 · 위치를 따르고, 지우면 다시 카메라를 따름(2026-10-15) |
| 2-2 | 스테레오 패닝 값: 정면 · 뒤 · 위 0.5/0.5, 오른쪽 0.2/1, 왼쪽 1/0.2(DEF-166, 2026-11-06) |
| 3 | 감쇠: Inverse 1/2·1/8, Max 밖 유지, Linear 절반·Max 무음, Exponential 1/4, Rolloff 0, Spatialize 끔 |
| 4 | 일시정지 중 무음, 재생 상태 유지, 재개하면 멈춘 자리에서 이어짐 |
| 5 | 액터·컴포넌트·부모를 끄면 멈춤(첫 샘플부터 무음), 다시 켜면 처음부터 |

| 9 | 저장소 시험 음원 세 개(OGG 포함)가 불러와지고 소리가 남 |

| 12 | `AUDIO_3D` 텍스트 왕복·정밀도·깨진 값 11종 거부 |

## 6. 시험용 음원

모두 ffmpeg 로 합성한 소리라 저작권 문제가 없습니다. `-fflags +bitexact` 로 만들어 다시 만들어도 같은
파일이 나옵니다(WAV 헤더 44바이트, 메타데이터 없음).

| 파일 | 내용 | 용도 |
|---|---|---|
| `assets/audio/Test_BeepLoop.wav` | 모노 1초. 0.15초 비프(880 Hz + 배음) 뒤 무음, 끝과 처음이 0 이라 이음매 없이 반복 | 방향·거리 확인 |
| `assets/audio/Test_Chime.wav` | 모노 1.5초 감쇠 차임 | 한 번 재생(Loop 끔) |
| `assets/audio/Test_NoiseLoop.ogg` | 모노 2초 핑크 노이즈, OGG Vorbis | Vorbis 경로, 넓은 대역 위치감 |
| `assets/prefabs/AudioProbe.hprefab` | 작은 초록 구 + `Test_BeepLoop.wav` 반복 재생 | 콘텐츠 브라우저에서 눌러 스폰 → Play |

```
ffmpeg -f lavfi -i "aevalsrc='if(lt(t,0.15),(0.32*sin(2*PI*880*t)+0.16*sin(2*PI*1760*t)+0.08*sin(2*PI*2640*t))*sin(PI*t/0.15),0)':s=48000:d=1" -ac 1 -c:a pcm_s16le -map_metadata -1 -fflags +bitexact -flags:a +bitexact Test_BeepLoop.wav
ffmpeg -f lavfi -i "aevalsrc='0.22*min(1,t*400)*exp(-2.5*t)*(sin(2*PI*660*t)+0.5*sin(2*PI*1320*t)+0.3*sin(2*PI*1980*t)+0.2*sin(2*PI*2970*t))':s=48000:d=1.5" -af "afade=t=out:st=1.25:d=0.25" -ac 1 -c:a pcm_s16le -map_metadata -1 -fflags +bitexact -flags:a +bitexact Test_Chime.wav
ffmpeg -f lavfi -i "anoisesrc=d=2:c=pink:r=48000:a=0.2:s=1" -ac 1 -c:a libvorbis -q:a 3 -map_metadata -1 -fflags +bitexact -flags:a +bitexact Test_NoiseLoop.ogg
```

콘텐츠 브라우저에서 음원 파일을 누르면 선택한 액터에 지정합니다. 오디오 컴포넌트가 없으면 붙이고,
선택이 없으면 경고 한 줄을 남깁니다(예전에는 아무 반응이 없었습니다).

|---|---|

| 항목 | 결정 |
|---|---|
| 저장 위치 | 이 PC 에 속한 값이라 실행 폴더의 `Config/editor_state.txt`(`audioOutput`, `audioHeadsetInVr`). 프로젝트 설정(`project.ini`)이 아닙니다 |

### 8-2. 구현

- **장치를 엔진 밖에서 소유**: `AudioSystem` 이 `ma_context` · `ma_device` 를 직접 만들고 `ma_engine_config::pDevice` 로 엔진에 연결합니다.
  장치를 바꿀 때는 엔진과 사운드를 그대로 두고 같은 `ma_device` 자리를 닫았다 다시 엽니다. 장치는 언제나 f32 · 2채널 · 48kHz 로 열어
  (실제 장치 형식과 다르면 miniaudio 가 변환) 엔진이 처음 본 형식이 바뀌지 않습니다. 그래서 **재생 중에 바꿔도 소리가 이어집니다**.
- **API**: `outputDevices()`(ID · 이름 · 시스템 기본 여부), `setOutputDevice(id)`(빈 문자열 = 시스템 기본, 운영체제에서 기본 장치를 바꾸면
  따라감), `setOutputOverride(id)`(잠시 다른 장치, 비우면 고른 장치로), `activeOutputName()`, `overrideActive()`(헤드셋 장치가 실제로 열렸는지).
  장치 없는 엔진(테스트)은 값만 기억합니다.
- **열 장치 순서(2026-11-06, DEF-146 · 147)**: 헤드셋(XR Play 동안) → 고른 장치 → 시스템 기본 순으로 열어 보고(`outputCandidates`), 목록에
  없거나 열리지 않은 후보(뽑힘 · 다른 앱의 독점 모드 등)는 경고하고 다음 후보로 갑니다. 예전에는 고른 장치가 열리지 않으면 소리가 없었고,
  헤드셋 장치가 없으면 고른 장치를 건너뛰고 시스템 기본으로 열었습니다. 대화상자의 "(headset during VR Play)" 는 헤드셋 장치가 실제로
  열렸을 때만 붙습니다.
- **잃은 장치(2026-11-06, DEF-145)**: 실행 중에 장치를 잃으면 miniaudio 는 장치를 멈춥니다(시스템 기본은 새 기본 장치로 옮겨 줌). 같은
  장치 판정에 장치가 돌고 있는지(`ma_device_is_started`)를 더해, 멈춘 장치는 대화상자에서 같은 장치를 다시 골라도 다시 엽니다. Play
  동안에는 tick 이 2초 간격으로 다시 열어 위 순서로 소리를 잇습니다(`checkOutput`, 장치가 돌면 상태 읽기 하나뿐). 고른 장치가 돌아와도
  자동으로 되돌아가지는 않습니다(대화상자에서 다시 고름). 자동 복귀는 장치 목록을 주기적으로 훑어야 해서 넣지 않았습니다.
- **장치 ID**: WASAPI 는 끝점 ID(`{0.0.0.00000000}.{GUID}`, UTF-16 → UTF-8, `hutf::fromUtf16`)를 쓰고, 대소문자를 무시하고 비교합니다.
  OpenXR 런타임이 알려 주는 헤드셋 장치 ID 와 같은 형식입니다. 다른 백엔드는 장치 이름을 씁니다.
- **헤드셋 장치**: `XrSystem` 이 인스턴스를 만들 때 `XR_OCULUS_audio_device_guid` 를 켜고 헤드셋 장치 ID 를 받아 둡니다
  (`headsetAudioOutputId()`). 이 확장은 `openxr_platform.h` 에서 Win32 정의 아래에 있어 windows.h 가 필요하므로, 확장 이름과 함수 모양만
  같게 두고 함수 주소를 런타임에서 받습니다. 엔진이 세션을 만들 때 `setOutputOverride(헤드셋)`, 세션을 끝낼 때 `setOutputOverride("")` 합니다.
- **장치 이름 표시**: UI 글꼴이 ASCII 만 그리므로 한국어 Windows 의 장치 이름("헤드폰(Oculus Virtual Audio Device)")에서 ASCII 가 아닌
  글자를 빼고, 남은 글을 감싼 괄호를 벗겨 보여 줍니다(`hutf::asciiLabel`). 로그 파일에는 원래 이름이 남습니다.

| 기본 기능 | 버스 · 보이스 예산 · 로딩 정책 · 도플러 · 콘 | miniaudio 에 대부분 있음(보이스 예산은 없음). 믹싱 골격 → 로딩 정책 → 한 번 재생 + 보이스 예산 → 콘 · 도플러 |

- 제외: Meta XR Audio SDK(독점 라이선스, 오픈 소스 결합 금지), Resonance Audio(2023-11 보관, 믹싱을 통째로 가져감), OpenAL Soft · 3D Tune-In ·
  BRT(LGPL · GPL).
- Quest 공식 예산 수치는 어느 쪽에도 없습니다. Meta 샘플 설정의 "동시 공간화 음원 64개"가 유일한 참고값이고, 실측이 필요합니다.
- Steam Audio 의 차폐 · 잔향 시뮬레이터는 쓰지 않습니다. 장면을 따로 관리해야 하고 반사 계산은 별도 스레드 · 굽기가 필요합니다.
  거리 감쇠는 miniaudio 에만, 차폐 판정은 하루카에만 두어 겹치지 않게 합니다.

조사하면서 miniaudio 소스에서 확인한 것:

- `ma_engine_node` 의 구성은 fader · resampler · spatializer · panner · gainer 뿐이라 **사운드에 저역 통과 필터가 없습니다.** 사운드 뒤에 노드를
  이어야 합니다(`ma_sound_config::pInitialAttachment`).
- 볼륨 변경은 기본값에서 계단식이지만 `volumeSmoothTimeInPCMFrames`(사운드) · `defaultVolumeSmoothTimeInPCMFrames`(엔진)로 보간할 수 있습니다.
- extras 의 `ma_reverb_node_init` 은 `verblib_initialize` 만 부르고 설정의 roomSize · damping · wet · dry 를 적용하지 않습니다. 그래서 verblib 를
  직접 감싼 노드를 만듭니다.
- 도플러 식 `(c − f·vls) / (c − f·vss)` 는 속도를 `c / f` 로 자르므로 잘린 값에서 분모가 0 입니다. 켤 때 하루카가 먼저 잘라야 합니다.
- 공식 예제 `examples/engine_steamaudio.c` 는 음원 → 청취자 방향(`ma_sound_get_direction_to_listener`)을 넘기는데, Steam Audio 는 청취자 → 음원을
  요구합니다. 옮길 때 부호를 고치고 시험으로 확인합니다.

### 9-3. 단계 0: 기반 (2026-11-06)

**음원별 노드 사슬.** 소리 하나를 보이스(`AudioVoice`, AudioSystem.cpp 안에 정의)로 감쌉니다. 예전에는 `ma_sound` 를 월드 그룹에 바로 붙였습니다.

```
ma_sound(디코딩 · 피치 · 거리 감쇠 · 패닝) ──▶ 보이스 필터 ──▶ 월드 그룹 ──▶ 엔진 출력
```

- 보이스 필터는 단계 1 에서 저역 통과 · 게인을 맡을 자리이고, 지금은 입력을 그대로 내보냅니다(`memcpy`). 잔향 센드와 HRTF 노드도 이 사슬에
  들어갑니다.
- 만들 때는 사슬의 끝부터(필터를 그룹에 붙인 뒤 사운드를 필터에 붙임), 정리할 때는 앞부터(사운드 → 필터) 합니다. 필터가 그룹 입력 목록에
  들어가는 자리 · 순서가 예전에 사운드가 들어가던 것과 같아서 섞는 합도 같습니다. 사운드 설정은 `ma_sound_init_from_file` 과 같고
  (`ma_sound_config_init_2`), 붙는 곳만 그룹 대신 필터입니다.
- 일시정지는 그대로 월드 그룹 정지입니다. 필터는 그룹 아래에 있으므로 그룹이 멈추면 읽히지 않습니다.
- 핸들은 `void*` 대신 형이 있는 `AudioVoice*` 입니다(`AudioComponent::voice_`, `AudioSystem::createVoice` · `destroyVoice` · `playVoice` · `stopVoice` ·
  `isVoicePlaying`).

**레이캐스트 제외 액터.** `PhysicsSystem::raycast(…, std::span<Actor* const> ignore = {})` 가 목록에 든 액터의 바디를 건너뜁니다(Jolt `BodyFilter`,
바디 사용자 값 = 액터 ID). 청취자 → 음원 레이가 음원 자신이나 청취자 리그의 충돌체에 맞으면 모든 소리가 막힌 것으로 나오기 때문입니다.
특히 볼록 셰이프 안에서 출발한 레이는 그 셰이프에 거리 0 으로 맞습니다(Jolt 기본, 시험으로 확인). 액터 단위라 자식 액터의 바디는 따로 넣습니다.

### 9-4. 단계 1: 차폐 + 회절 근사 (2026-11-06)

UE 내장 차폐와 같은 항목에, Steam Audio Volumetric 식 일부 차폐를 더했습니다. 공간화를 켠 소리에만 걸리고 기본은 꺼짐입니다.

| 디테일 행(Spatialize 아래) | 필드(`AudioOcclusionSettings`) | 기본값 | 의미 |
|---|---|---|---|
| Occlusion | `enabled` | 꺼짐 | 켜면 아래 행이 나타납니다 |
| Occluded Low Pass | `lowPassHz` | 1200 Hz | 완전히 막혔을 때의 저역 통과 차단 주파수(20 ~ 20000) |
| Occluded Volume | `volume` | 0.4(≈ -8 dB) | 완전히 막혔을 때의 볼륨 배율(0 ~ 1) |
| Occlusion Time | `smoothTime` | 0.1 s | 막힘 ↔ 열림 전환의 시간 상수(0 ~ 10, 0 이면 즉시) |
| Source Radius | `radius` | 0 m | 0 이면 레이 하나(막힘/열림), 0 보다 크면 표본 9개로 일부 차폐(0 ~ 10) |

씬 파일은 오디오 블록의 `occlusion` 키입니다(예: `1 1200 0.4 0.1 0.5`). `attenuation` 과 같이 토큰 다섯 개를 정확히 요구합니다.

**판정(게임 스레드, `AudioSystem::tick`).** 차폐 정도 o 는 0 = 열림, 1 = 완전히 막힘입니다.
- 청취자 → 음원 선분이 물리 충돌체에 막히는지 `PhysicsSystem::raycast` 로 봅니다. 반지름이 있으면 음원 + 청취자 → 음원 축에 수직인 원판
  둘레 8점을 표본으로 쓰고, 둘레 표본은 청취자 → 표본, 표본 → 음원 두 선분 중 하나라도 막히면 막힘입니다(음원 옆 벽 너머의 표본은 청취자에게
  보여도 소리가 거기까지 가지 못함). o = 막힌 표본의 비율이라, 벽 모서리를 돌 때 소리가 서서히 바뀝니다(값싼 회절 근사).
- 레이에서 뺄 액터: 음원 액터와 그 자손 · 조상, 활성 카메라 액터와 그 조상(XR 이면 리그). 볼록 셰이프 안에서 출발한 레이는 거리 0 으로 맞기
  때문입니다(9-3).
- 소리마다 0.1 s(`hocc::kRetraceSec`) 간격으로 다시 판정하고, 판정 시점은 소리마다 황금비 위상으로 엇갈려 한 프레임에 몰리지 않습니다.
  **처음 만들 때와 멈췄다 다시 재생할 때는 바로 판정해 그 값으로 시작합니다**(UE 의 비동기 트레이스는 첫 결과 전에 소리가 바뀌는 문제가 알려져 있음).
- 판정 사이에는 지수 평활(`hocc::smooth`, 시간 상수 `smoothTime`)로 옮기고, 목표에 1e-3 안으로 오면 목표로 맞춥니다.
- 게인 = `1 + (volume − 1)·o`, 차단 주파수는 로그 축 `exp(lerp(ln 20000, ln lowPassHz, o))`(`AudioOcclusion.hpp`).

**적용(오디오 스레드, 보이스 필터).** 1차 저역 통과 두 단(12 dB/옥타브, `a = exp(−2π·fc/fs)`) + 게인입니다. 게임 스레드가 원자 값(켜짐 · 게인 · 계수 ·
처음 값 맞춤 · 상태 비우기)을 넘기고, 필터는 블록 시작에 한 번 읽습니다. 게인은 블록 안에서 선형으로 옮겨 계단 잡음을 막습니다. **o = 0 이면 필터를
건너뛰어** 출력이 예전과 비트 단위로 같습니다(14절이 그대로 통과). 통과하던 소리에 필터가 걸리기 시작하면 상태를 첫 입력으로 맞춰 튐을 막고,
멈추면(`stopVoice`) 상태를 비웁니다.

**비용(추정, Quest 실측 전).** 레이 하나인 소리는 초당 10개, 반지름이 있으면 초당 최대 170개(표본 9개 × 선분 최대 2개 − 1)입니다. 필터는 샘플당
곱셈 · 덧셈 몇 개입니다. Quest 에서 재는 것은 소리가 켜진 뒤(Android 는 지금 `noAudio`)의 일입니다.

**알려진 한계.**
- 소리를 막는 것은 RigidBody 의 상자 · 구 · 캡슐뿐입니다(사용자 결정). 렌더 메시만 있는 벽은 막지 않습니다.
- 재질별 투과(벽 두께 · 재질에 따라 조금 새어 나옴)와 잔향 센드에 차폐를 곱할지는 잔향 단계에서 정합니다.
- 청취자가 레이에서 빼지 않은 다른 충돌체 안에 서 있으면 모든 소리가 막힙니다(볼록 셰이프 안 출발).
- 진짜 회절(문을 돌아 들어오는 방향)은 방 · 포털 단계에서 합니다.

**확인.**
- 오디오 테스트 15절 31항목: 순수 계산(게인 · 로그 축 · 평활 · 표본점 9개가 축에 수직), 설정 텍스트 왕복 · 깨진 값 14종 · 컴포넌트 직렬화,
  실제 물리 벽(4 m × 4 m 판) 뒤 200 Hz 는 0.3892(해석값 `0.4 × |H(200)|²` = 0.3892), 8 kHz 는 0.00965(해석값 0.00965), 벽이 없으면 차폐를 끈 소리와
  크기가 같음(필터를 건너뜀), 새 소리는 첫 블록부터 막힌 크기, 벽을 치우면 47틱(0.78 s)에 걸쳐 줄어들기만 하다가 정확히 0, 멈춘 동안 벽이 생기면
  다시 재생한 다음 틱에 바로 막힘, 음원 자신 · 부모 · 청취자의 충돌체와 2D 소리는 막힘이 아님, 벽 모서리 뒤 3/9 · 한가운데 뒤 1 · 먼 쪽 0,
  음원 옆 벽 너머 표본 3/9.
- 변이 10개 모두 의도한 검사에 잡힘: 음원 · 조상 · 청취자를 빼지 않음, 처음 값으로 시작하지 않음, 게인을 적용하지 않음, 한 단만, 표본 → 음원
  선분 생략, 멈춘 뒤 다시 판정하지 않음, 필터를 건너뛰지 않음, 차단 주파수를 선형 축으로. 처음에는 부모 · 카메라 검사가 판정 간격보다 짧게
  기다려 살아남은 변이가 있었고, 기다리는 시간을 늘려 고쳤습니다.
- Release · Debug 경고 0, 시험 24개 통과(검사 1,226 → 1,257), Android `HarukaGame` 링크 통과. 소리를 귀로 듣는 실기 확인(에디터 Play)은 2026-11-09 에 통과했습니다(9-6 끝).

### 9-5. 단계 2: 잔향 (2026-11-06)

UE · Unity · FMOD 와 같은 **청취자 구역 + 공용 리버브 하나 + 음원별 센드** 구조입니다(조사 B 의 권장안).

```
ma_sound ──▶ 보이스 필터 ─[출력 0: 직접음]──────────────────▶ 월드 그룹 ──▶ 엔진 출력
                         └[출력 1: 센드 × 센드 게인]──▶ 리버브 ──┘
```

- **보이스 필터에 출력을 하나 더했습니다**(별도 스플리터 노드 대신). 출력 1 = 차폐 필터 뒤의 소리 × 센드 게인(블록 안 선형 보간)이라, 차폐된 소리는
  잔향도 줄어듭니다. 입력이 있는 노드는 출력이 하나든 둘이든 같은 캐시 경로(480 프레임 단위)로 처리되고, 한쪽 출력이 읽히지 않아도(리버브가
  멈춤) 다음 주기에 정상 처리됩니다(miniaudio 의 출력별 읽음 표시, 소스로 확인). 출력 0 은 예전과 같아서 14절이 그대로 통과합니다.
- **리버브는 월드 그룹 안쪽**에 있어서, 일시정지(그룹 정지) 동안 꼬리도 함께 얼었다가 재개하면 이어집니다. 그룹 밖에 두면 일시정지 중에도
  꼬리가 울립니다(변이로 확인).
- **verblib 를 직접 감쌌습니다**(`Verblib.hpp`, 구현부는 `MiniaudioImpl.cpp`). extras 의 `ma_reverb_node` 는 설정을 적용하지 않고 매개변수 변경이
  오디오 스레드와 겹치기 때문입니다. 게임 스레드가 원자 값(방 크기 · damping · 폭 · 크기 · 비우기)을 넘기고, 오디오 스레드는 블록 시작에 바뀐
  것만 verblib 에 넣습니다. 출력은 잔향만(wet 1 · dry 0)이고, 크기는 블록 안에서 선형으로 옮깁니다. 엔진은 48 kHz 고정이라 샘플레이트 배율을
  2 로 줄여 인스턴스가 약 199 KiB 입니다.
- **리버브는 멈춘 채 시작합니다.** 청취자가 구역에 들어가면 꼬리를 비우고 시작하며, 구역을 모두 벗어나 크기가 0 이 되면 다시 멈춥니다. 멈춘
  노드는 읽히지 않아 그동안 CPU 를 쓰지 않고, 출력은 잔향이 없던 때와 비트 단위로 같습니다. Stop(`onEndPlay`) · Play 시작에서도 멈춥니다.

**잔향 구역(`ReverbZoneComponent`, 디테일 이름 "Reverb Zone").**

| 행 | 필드 | 기본값 | 의미 |
|---|---|---|---|
| Unbounded | `unbounded` | 꺼짐 | 켜면 위치와 무관한 장면 기본 잔향(야외 등). 아래 모양 행을 숨김 |
| Shape | `shape` | Box | Box(반 크기 HalfX · Y · Z, 기본 5 · 3 · 5 m) 또는 Sphere(Radius 5 m). 크기에 액터 크기를 곱하고, 위치 · 회전은 액터를 따름 |
| Blend Distance | `blendDistance` | 1 m | 경계 밖 이 거리 안에서는 크기가 1 → 0 으로 줄어듦 |
| Priority | `priority` | 0 | 겹치면 높은 구역. 같으면 더 깊이 들어간(가중치가 큰) 구역, 그것도 같으면 액터 ID 가 작은 구역 |
| Decay Time | `decayTime` | 1.5 s | 잔향 시간 RT60. verblib 로 만들 수 있는 약 0.61 ~ 10.7 s 로 자름 |
| Damping | `damping` | 0.5 | 높을수록 고역이 빨리 줄어듦 |
| Width | `width` | 1 | 스테레오 폭 |
| Level | `level` | 1 | 잔향 크기(0 ~ 4) |
| Fade Time | `fadeTime` | 0.5 s | 이 구역으로 바뀔 때의 시간 상수(UE 의 Fade Time). 구역을 모두 벗어나면 마지막 구역의 값으로 줄어듦 |

- 판정은 청취자 위치 하나라 물리가 필요 없습니다(XR 이면 머리 위치). 구역을 벗어날 때는 크기만 줄이고 다른 매개변수는 그대로 두어 꼬리의 성격이
  갑자기 바뀌지 않게 합니다. 구역 사이를 옮길 때는 리버브 하나의 매개변수를 따라가게 합니다(UE · FMOD · Unity 방식, 크로스페이드 아님).
- **잔향 시간 → 방 크기**: verblib 의 콤 필터 8개 평균 지연 31.2 ms 와 되먹임 g(방 크기 0 ~ 1 = 0.7 ~ 0.98)로 `g = 10^(−3 × 0.0312 / RT60)`
  (`hrev::roomSizeForDecay`). 저역 기준이고, 실제 꼬리는 콤마다 지연이 달라 조금 길게 잡힙니다(아래 확인 1.58 s).

**소리별 센드(`AudioComponent`, Spatialize 아래).** Reverb Send(`reverbSend`, 기본 1, 0 ~ 2)와 Reverb Reach(`reverbReach`, 기본 0.5, 0 ~ 1).
센드 게인 = `send × g(d)^(−reach)`(상한 10)입니다. 센드 갈래는 이미 거리 감쇠 g(d) 를 받았으므로, 잔향 크기는 `send × g(d)^(1 − reach)` 가 됩니다.
reach 0 이면 직접음 대 잔향 비율이 일정하고, 1 이면 잔향 크기가 거리와 무관합니다(Meta XR Audio 의 Reverb Reach 와 같은 뜻). g(d) 는 miniaudio 와
같은 식으로 게임 스레드가 셉니다(`hrev::attenuationGain`). 2D 소리는 보내지 않습니다(UE 의 2D 기본 센드 0).

**비용(추정, Quest 실측 전).** 리버브 하나에 프레임당 약 210 부동소수 연산(XR2 큰 코어의 1% 안쪽)과 약 199 KiB. 구역 밖에서는 0. 센드는 소리마다
샘플당 곱셈 하나입니다.

**알려진 한계.** 0.6 s 보다 짧은 방은 만들 수 없습니다(damping 과 낮은 Level 로 흉내). 초기 반사 · 프리딜레이가 없고, 꼬리 길이가 크게 다른 구역
사이의 크로스페이드, 청취자와 다른 구역에 있는 소리의 처리(UE 의 Interior/Exterior), 음원 구역별 리버브는 다음 단계 후보입니다. 에디터에서 구역
상자를 선으로 그리지 않습니다(감쇠 반경 표시와 함께 할 일, 7절).

**확인.**
- 오디오 테스트 16절 34항목: 잔향 시간 ↔ 방 크기 왕복(0.8 · 1.5 · 3 · 7 s), 거리 감쇠 식(Inverse · Linear · Exponential), 센드 게인(reach 0 · 1 · 0.5,
  상한), 구역 가중치(상자 · 구, 회전 · 크기 · unbounded), 직렬화와 깨진 값. 실제 리버브로: 짧은 잡음 뒤 꼬리의 0.2 s · 1.2 s 크기 차이로 잰 잔향
  시간이 1.5 s 설정에서 **1.58 s**, 3 s 설정에서 **3.07 s**. damping 1 이면 꼬리가 빨리 줄어듦. 4 m / 1 m 꼬리 비율이 reach 0 에서 **0.250**,
  reach 1 에서 **1.000**. 2D 소리 · 센드 0 은 꼬리가 정확히 0. 일시정지 중 꼬리도 무음, 재개하면 이어짐(비율 0.81). Stop 하면 리버브가 멈추고,
  다음 Play 에서 지난 꼬리가 비워져 있음. 우선순위 · 깊이 · 액터 ID 순서, 경계 밖 절반 거리에서 크기 절반, 구역을 벗어나면 1.72 s 에 걸쳐 줄다가 멈춤.
- 변이 11개 모두 의도한 검사에 잡힘: 리버브를 그룹 밖에, Stop 에서 멈추지 않음, 시작할 때 꼬리를 비우지 않음, reach 무시, 2D 도 보냄, 우선순위 ·
  ID 순서 뒤집기, 가중치 무시, 잔향 시간을 선형으로 바꿈, 멈추지 않음, damping 무시. 처음에는 "멈출 때 꼬리 비우기"를 빼는 변이가 살아남았는데,
  시작할 때 늘 비우므로 중복이라 코드에서 없앴습니다.

  넣었습니다(MIT No Attribution 이라 의무는 아님). 귀로 듣는 확인(에디터 Play)은 2026-11-09 에 통과했습니다(9-6 끝).

### 9-6. 단계 3: HRTF (2026-11-06)

**결정.** Steam Audio 4.8.1(Valve, Apache-2.0)의 바이노럴 효과를 씁니다. 릴리스 ZIP 을 받아 크기를 잰 뒤(Windows `phonon.dll` 50.5 MB, Android
`libphonon.so` strip 뒤 6.9 MB, 추가 의존 라이브러리 없음, 16 KB 페이지 정렬) 사용자가 "Steam Audio 로 진행"을 골랐습니다. 크기 대부분은 HRTF 와
무관한 시뮬레이터 코드(Embree · IPP 등)입니다. 노드 인터페이스(`hhrtf::Backend` · `Renderer`, `AudioHrtf.hpp`)는 나중에 직접 구현(공개 HRTF 데이터 +
컨볼루션)으로 바꿔 끼울 수 있게 두었습니다.

```
ma_sound(패닝 계수 0: 거리 감쇠 · 콘 · 도플러만) ──▶ 보이스 필터 ─[출력 0]──▶ HRTF 노드 ──▶ 월드 그룹 ──▶ 엔진 출력
                                                               └[출력 1: 센드]──▶ 리버브 ──┘
```

**켜는 때(`EHrtfMode`).** HRTF 는 헤드폰 · 헤드셋용이라 스피커로 들으면 오히려 어색합니다.

| 모드 | 동작 |
|---|---|
| Auto(기본) | XR 세션이 있는 동안만 켬(Engine 이 세션을 만들고 지울 때 `setXrActive`). Quest 단독 실행은 늘 XR 이라 켜짐 |
| On | 언제나(데스크톱에서 헤드폰으로 들을 때) |
| Off | 쓰지 않음(패닝) |

에디터는 Edit > Audio Output... 의 "3D audio (HRTF)" 줄로 바꿉니다(누를 때마다 Auto → On → Off, 바로 적용, `Config/editor_state.txt` 의
`audioHrtf=auto|on|off`). 게임 실행 파일은 Auto 입니다(설정 화면은 장치 선택 화면과 함께 나중).

**사슬.**
- HRTF 노드는 HRTF 가 켜진 **공간화 소리에만** 사이에 들어갑니다. 처음 필요할 때 만들고, 끄면 보이스 필터를 그룹에 다시 바로 붙입니다(노드는 남은
  꼬리를 낸 뒤 쉼). 그래서 HRTF 가 꺼진 동안의 출력은 예전과 바이트 단위로 같습니다(14절이 기본 상태로 확인). 2D 소리는 거치지 않습니다.
- miniaudio 의 공간화는 끄지 않고 패닝 계수(`directional_attenuation_factor`)만 0 으로 둡니다. 끄면 거리 감쇠 · 콘 · 도플러가 함께 사라집니다.
  계수 0 이면 채널 게인이 1 이라 두 채널이 같고, 노드가 평균을 내 모노로 HRTF 에 넣습니다(스테레오 음원은 한 점으로 모음, Steam Audio 와 같음).
- 차폐 필터 · 잔향 센드는 HRTF 앞(보이스 필터)에 있습니다. 잔향에는 HRTF 를 걸지 않습니다(UE · Steam Audio 의 일반 구조).
- 방향은 게임 스레드가 틱마다 청취자 기준 단위 벡터(**청취자 → 음원**, +X 오른쪽 · +Y 위 · -Z 정면)로 넘깁니다. miniaudio 의 공식 예제
  (`engine_steamaudio.c`)는 반대 방향(음원 → 청취자)을 넘기므로 따라 하지 않았고, 귀 사이 시간차의 부호로 확인했습니다. 청취자에게 0.1 m 보다
  가까우면 공간화 정도(`spatialBlend`)를 거리에 비례해 줄여 머리 한가운데로 모읍니다(거리 0 에서는 방향이 없음).
- 보간은 쌍선형입니다(가장 가까운 측정 방향 4개). 최근접은 싸지만 고개를 돌릴 때 필터가 갑자기 바뀌는 소리가 들립니다(Steam Audio 문서).

**FIFO 와 꼬리.** Steam Audio 는 정해 둔 블록 크기로만 처리하는데, miniaudio 노드는 부를 때마다 프레임 수가 다를 수 있습니다. 노드가 256 프레임씩
모아 처리하므로 직접음이 정확히 256 프레임(5.3 ms) 늦습니다. 출력은 부르는 블록 크기와 무관합니다(시험). 소리가 끝나면 FIFO 와 필터 꼬리가 남는데,
보통 노드처럼 입력이 없을 때 처리를 건너뛰면 끝에서 잘려 튑니다. 그래서 노드를 `CONTINUOUS_PROCESSING · ALLOW_NULL_INPUT` 으로 두고, 남은 출력을
다 낸 뒤에는 구현을 부르지 않습니다. 구현하며 확인한 함정이 셋 있습니다.
- miniaudio 는 입력 노드가 붙어 있으면 그 노드가 아무것도 내지 않아도 NULL 이 아니라 **0 으로 채운 버퍼**를 줍니다(NULL 은 붙은 노드가 없을 때만).
  그래서 "입력 없음" 은 NULL 이거나 모두 0 인 것으로 봅니다.
- 쉬는 동안 입력이 붙어 있으면 무음을 내야 합니다. 0 프레임을 내고 입력만 쓰면 miniaudio 가 같은 주기에 입력을 또 읽어 처리 고리가 끝나지
  않습니다(변이로 확인: 시험이 멈춤). 사슬에서 뺀 노드(입력 NULL)는 0 프레임을 냅니다.
- Steam Audio 의 처리 함수(`iplBinauralEffectApply`)는 입력이 무음이어도 언제나 "꼬리 남음" 을 돌려줍니다. 그래서 무음 블록은 `iplBinauralEffectGetTail`
  로 꺼냅니다(문서의 규칙과 같음). 처음에는 처리 함수로만 돌려 소리가 끝난 뒤에도 노드가 계속 돌았습니다(시험이 잡음).
- 일시정지(그룹 정지) 동안은 읽히지 않아 FIFO 가 그대로 있다가 이어지고, Stop(되감기)은 FIFO 와 구현 상태를 비웁니다.

**크기 맞춤.** 패닝을 끄면 정면 음원이 채널마다 0.5 → 1(+6 dB)이 되고, 기본 HRTF 는 정면에서 다시 약 +3.5 dB(왼쪽) · +5.5 dB(오른쪽) 키웁니다.
출력에 0.59 를 곱해 두 귀의 거듭제곱 평균을 패닝일 때와 맞췄습니다. 그래서 HRTF 를 켜고 꺼도 정면 소리의 크기가 같습니다. 기본 HRTF 데이터는
좌우 대칭이 아닙니다(정면에서 왼쪽이 약 2 dB 작고, 바로 위 음원은 왼쪽이 약 3 dB 작음).

**배포 · 빌드.**
- 라이브러리는 링크하지 않고 실행 중에 엽니다(Windows 는 실행 폴더와 System32 만 찾음, Android 는 APK 의 `lib/arm64-v8a`). 그래서 실행 파일의 가져오기
  목록이 바뀌지 않고, 파일이 없으면 경고 한 줄을 남기고 패닝으로 계속합니다. 처음 HRTF 가 켜질 때 엽니다(시작이 느려지지 않게).
- CMake(`cmake/SteamAudio.cmake`)가 릴리스 ZIP(181 MB)을 빌드 폴더마다 한 번 받아 SHA-256 을 확인하고, 헤더 · 그 플랫폼의 라이브러리 · `THIRDPARTY.md`
  만 풀고 ZIP 을 지웁니다. 이미 받은 ZIP 은 `-DHARUKA_STEAM_AUDIO_ZIP=<경로>`, HRTF 없이 빌드하려면 `-DHARUKA_STEAM_AUDIO=OFF`.
- Windows 는 실행 폴더와 배포 ZIP 에 `phonon.dll` 을 넣고, Android 는 `package_apk.py` 가 `libphonon.so` 를 strip 해 넣습니다. 서드파티 고지에 Apache-2.0
  원문 · 저작권 표시와 `THIRDPARTY.md`(IPP · FFTS · PFFFT · MySOFA · Embree · CIPIC HRTF 등)를 넣습니다. 이름은 출처 표시로만 씁니다(TRADEMARK_RIGHTS.md).

**비용.** 이 PC(데스크톱 한 코어)에서 256 프레임 블록 하나가 약 5 µs, 소리 하나에 실시간의 0.1% 입니다. Quest Pro 실측은 남았습니다(조사 C 의 추정:

## 10. 들리지 않는 소리의 가상화 · 최대 거리 밖 무음 (2026-11-17)

수학 보강([Math_Reinforcement.md](Math_Reinforcement.md) S3)의 소리 부분입니다.

- **가상화.** 매 틱 예상 게인 = 볼륨 × 거리 감쇠(miniaudio 와 같은 식, `hvirt::distanceGain`) × 차폐 게인을 구해, −60 dB(0.001) 아래로 내려가면
  `ma_sound_stop` 으로 믹싱(디코딩 · 공간화 · 보이스 필터 · HRTF)을 멈추고 재생 위치만 원본 샘플률 × 피치로 셉니다. −54 dB(0.002) 위로
  올라오면 센 위치로 되감고 필터 · HRTF 상태를 비운 뒤 다시 시작합니다(6 dB 이력 띠). 2D 소리는 거리와 무관해 가상화하지 않습니다.
  일시정지(월드 그룹 멈춤) 동안은 위치도 멈춥니다. 반복이 아닌 소리가 들리지 않는 채로 끝에 닿으면 끝난 것으로 둡니다. `isPlaying` 은 가상
  보이스도 재생 중으로 봅니다. 길이 · 샘플률을 아직 모르는 비동기 디코딩 초기에는 가상화하지 않습니다.
- **최대 거리 밖 무음(`silentBeyondMax`).** 기본(끔)은 miniaudio · OpenAL 처럼 최대 거리 밖에서 그 거리의 값에 머뭅니다(Inverse 기본값 min 1 ·
  max 100 이면 0.01 = −40 dB 라 가상화에도 닿지 않음). 켜면 곡선을 (g − g_max) / (1 − g_max) 로 다시 맞춰 모양은 같고 최대 거리에서 정확히
  0 이 됩니다(UE Falloff Distance 의미). rolloff 0 이면 안 1 · 밖 0 입니다. miniaudio 는 이 곡선을 모르므로 엔진이 배율
  distanceGain ÷ miniaudioGain 을 볼륨에 곱합니다. 씬 파일에는 AUDIO_3D 줄을 늘리지 않고 `silentBeyondMax=1` 키를 켰을 때만 씁니다.
- 시험(`audio_system` 191 → 210): 감쇠 세 모델 값, 이력 띠, 위치 진행(반복 · 끝남), 0.5 초 가상 뒤 이어 낸 위치 25,279 프레임(기대 약 25,280),
  stop 이 가상 상태를 풂, 2D 제외, 무음 곡선 5 m 비율 0.5556(계산 0.556) · 최대 거리 밖 무음과 가상화, 씬 파일 왕복. 헤드셋 확인: 시험 장면
  `MathProbe` 의 두 소리(무음 켬 · 끔)로 서서히 사라짐 · 이어 들림 확인.
